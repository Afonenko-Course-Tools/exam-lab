## Рецензия перед началом

- Windows допускается к компонентным пробам. Адресный ACL для SID, полученного
  после входа Guest, оставляет интервал до применения правила. Для общего
  кандидата нужен подтверждённый порядок допуска первого и следующего Guest,
  включая частичный Apply. Проверяется штатный механизм до рассмотрения новых
  средств. Аудиторный `exam` отказывает до изменений, `FullReady=false`.
- В Deployment выделяется один экземпляр PL для одной работы. Изоляция адреса
  должна действовать и после LTI, включая ранее открытую сессию и прямой доступ
  к сервису. Проверка нового LTI-запуска на Gateway сохраняет существующий UID
  и требует подтверждённого источника из цепочки Squid и Nginx. Учебные тома
  и данные остаются в своих контурах.
- Wazuh получает одно Windows-событие. Локальное подтверждение под существующим
  администратором сохраняет гостевой сеанс и ответ. Видимость после Task View
  проверяется из Guest. IP используется для сопоставления наблюдений с указанием
  неоднозначности, если она есть.

## Допуск и незакрытые условия

Серверная fixture принята для повторения локальной пробы на зафиксированных
версиях. Общий Windows-кандидат не принят. `FullReady=false`; штатный `exam`
сохраняет ранний отказ. Сквозной цикл из Windows Guest со сдачей и возвращением
в обычный режим — `NOT_TESTED`.

| Граница | Статус | Условие повторной проверки и владелец |
| --- | --- | --- |
| Допуск первого и следующего Guest до чтения | `FAIL` | exam-lab должен подтвердить штатный момент вступления в силу на фактическом токене. Плитка после `prepare` уже видна без ограничений. Атрибуция провайдера и сценарий частичного Apply требуют запуска на VM. |
| Guest, ACL, виртуальный USB, IDEA | `NOT_TESTED` | Windows-оператору нужен разрешённый интерактивный Guest. Проверить чтение по точному пути, ротацию профиля, новый и переподключённый USB, сохранение и повторное открытие проекта. NTFS-исполнитель сохранил синтетические fixtures. |
| IPv6, прямой JVM HTTPS, совместная политика Windows | `NOT_TESTED` | Сетевой исполнитель проверяет разрешённый до Apply двусторонний маршрут. IPv4 echo и Java HTTPS через Squid подтверждены отдельно. Для совместного `normal` нужны действующие USB и сеть до отключения адаптера и Squid. |
| Тревога на экране Guest и офлайн-подтверждение | `NOT_TESTED` | exam-lab и Deployment должны связать событие с сеансом, проверить Task View, отказ записи и подтверждения из Guest и сохранить проект с ответом. DHCP-адрес служит только сетевым наблюдением. |
| Аудитория | `NOT_TESTED` | Владелец сопровождает проверку внешней Moodle, известной подсети, целевой русской Windows, физических USB и работы преподавателя на согласованном ПК. |
| Постоянный Wazuh в Proxmox | `NOT_TESTED` | Deployment проверяет Terraform, Ansible и сохранность томов на отдельной VM. В этой кампании локальный single-node достаточен для пробы правила. |

Общий рецензент архитектуры принял штатный Native-импорт и подтверждённую
сервером автоматическую сдачу, изоляцию экзаменационной fixture, узкий Moodle
ACL, DHCP и адресное снятие сети под администратором, а также правило Wazuh на
синтетическом EventChannel. Общий допуск закрыт, пока отсутствует проверенная
граница до первого доступа Guest. Задачу можно исследовать штатными механизмами
Windows в существующем компоненте, без нового LogonUI или сервиса авторизации.

Рецензент эксплуатации подтвердил видимый результат `Score` и `Test Results`
на серверной fixture, читаемость обычных файлов и виртуальной флешки после
снятия источников, а также запуск Java, Git и TCP в `labstudent`. Принятый
административный `normal` подтверждает снятие собственных настроек в записанных
условиях. Для общего экзаменационного сценария остаются фактический Guest,
открытие проекта в IDEA и офлайн-восстановление с совместными ограничениями.

## Действия преподавателя на испытательном стенде

Перед допуском проверьте версию и принятый результат общего входа. На исходной
версии `d30e405` допуск к сквозному экзамену закрыт. Для компонентных проверок
используется одноразовая VM с отдельной консолью администратора.

1. Перед выходом Guest получите подтверждение сдачи от PrairieLearn. При его
   отсутствии оставьте проект и ответ открытыми под наблюдением преподавателя.
   Если выход необходим, сначала согласуйте место сохранения ответа и убедитесь,
   что сохранённая копия открывается. На проверенном серверном стенде после
   `Save & Grade` появились `Score: 6/6 (100%)` и `Test Results`. Ручная часть
   осталась на проверке. Для другой работы или неясного статуса дождитесь её
   серверного подтверждения и держите ответ открытым.
2. В повышенном PowerShell выполните `Start-ScheduledTask -TaskName ExamLab-Local-normal`.
   Команда запускает задачу и оставляет гостевой сеанс открытым. При активном
   непривилегированном сеансе действующая USB-политика в исходном кандидате
   может блокировать снятие. При таком отказе сохраните ответ по шагу 1 до выхода
   Guest, затем повторите команду.
3. Дождитесь, пока `Get-ScheduledTask -TaskName ExamLab-Local-normal` выйдет из
   `Running`. В `Get-ScheduledTaskInfo -TaskName ExamLab-Local-normal` сопоставьте
   `LastRunTime` с текущим запуском и проверьте `LastTaskResult=0`. В свежем журнале
   `%ProgramData%\ExamLab\normal.log` проверьте `OwnSourceNormal=true`.
   Ошибка, частичное снятие или старый журнал требуют разбора. При
   `EffectiveMode=Unconfirmed` после снятия источников откройте обычную учётную
   запись и проверьте прежний проект, чтение USB и сеть после восстановления связи.
