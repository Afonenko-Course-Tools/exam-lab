# Опрос контроллера при запуске Windows

Установщик локального пилота поддерживает необязательную регистрацию ПК.
Планировщик Windows запускает `ExamLab-Controller-Poll` от SYSTEM при
включении, до входа. Первый опрос запускается сразу. После успешного цикла
пауза равна остатку 15 секунд от его начала и составляет минимум одну секунду.
После ошибки действует пауза 15 секунд с момента завершения цикла. Задача
допускает один экземпляр, запрос ограничен
восьмью секундами. Поздний старт сервера и потеря связи оставляют локальные
политики в текущем состоянии.

Контроллер из Deployment выдаёт назначение заранее установленного действия
и получает результаты. Gateway отвечает за вход и учебную личность, курсы
и Platform — за задания и оценивание. Регистрация ПК подтверждает отправителя
опроса независимо от DHCP. Связь с Windows Guest и пользователем Moodle
или PrairieLearn проверяется отдельно.

## Установка

На существующей Windows откройте повышенный PowerShell 7 x64.
Возьмите административный комплект переключателя, официальные LGPO и
PolicyFileEditor, объявленную конфигурацию ПК и приватный файл регистрации.
В файле регистрации три поля. `url` содержит полный HTTPS-адрес
`/exam/v1/poll`, `deviceId` содержит идентификатор ПК, `token` содержит
выданный администратором контроллера токен. Передавайте файл через защищённый
административный канал и храните вне Git, общедоступной поставки и журналов.

Скачайте публичный корневой сертификат DER из административного комплекта.
Для стенда комплект выдаёт администратор Deployment, для организации — её
администратор доверия. Сверьте SHA-256 с отпечатком из отдельного доверенного
канала. Закрытые ключи остаются у администратора доверия. Корневой сертификат
входит в постоянную административную подготовку этого компьютера. Установщик
проверяет SHA-256, действительность и назначение CA, добавляет его в
`LocalMachine\Root` и сверяет запись по отпечатку. Повтор подтверждает
существующую запись, остальные сертификаты сохраняются. Для уже доверенной
цепочки передавайте регистрационный файл без дополнительных сертификатов.
При запуске вне ZIP-поставки держите `ExamLabRootTrust.ps1` рядом с
`Install-LocalPilot.ps1`, если передаёте сертификаты.
Для нескольких корней передайте одинаковое число путей и отпечатков в
одинаковом порядке.

```powershell
.\setup\Install-LocalPilot.ps1 -LGPOPath $lgpo -PolicyFileEditorPath $pfe -ConfigurationPath $pc -ControllerConfigurationPath $registrationFile -TrustedRootCertificatePath $publicRoot -TrustedRootSha256 $verifiedSha256
```

Регистрация и результаты находятся в приватном `%ProgramData%\ExamLab`.
Контроллер проверяет токен, привязанный к конкретному ПК. Клиент проверяет
TLS-цепочку и имя штатными средствами Windows, подключается напрямую к
заданному адресу и отклоняет редиректы. Он передаёт токен только в заголовке
Authorization по этому HTTPS-соединению. Смена токена того же ПК выполняется
повторной установкой. Новый URL или идентификатор требуют отдельной
административной операции, чтобы сохранить монотонную ревизию назначений.

После установки задача стартует при следующей загрузке. Для проверки
без перезагрузки или возобновления опроса после переустановки выполните
`Start-ScheduledTask -TaskName ExamLab-Controller-Poll`. Подготовку Shared PC и
локальное восстановление обслуживают фиксированные административные задачи
из [инструкции пилота](local-pilot.md).

Для проверки HTTPS из JDK 25 используйте хранилище Windows для конкретного
процесса. Edge пользуется штатным доверием Windows.

```powershell
& $java '-Djavax.net.ssl.trustStore=NONE' '-Djavax.net.ssl.trustStoreType=Windows-ROOT-LOCALMACHINE' .\tests\NetworkProbe.java https $serviceUrl
```

Проверьте успешное соединение с доверенным именем и отказ с чужим именем
или неизвестным издателем. Для отказа не требуется менять доверие в целом.
Прокси нового Guest настраивается отдельно от постоянной установки доверия.

## Состояние и локальное завершение

POST `/exam/v1/poll` передаёт идентификатор устройства и последний результат
либо `null` до появления результата. Ответ содержит этот же идентификатор,
режим `normal` или `exam`, положительную монотонную ревизию и уникальный
`examId` для нового экзамена. Для `normal` поле `examId` равно `null`.
Меньшая ревизия, изменение назначения на той же ревизии и неверный ответ
отклоняются. Очередной успешный обмен передаёт результат предыдущего действия.

- `controller-health.json` содержит UTC загрузки, первой попытки, первого и
  последнего принятого ответа, состояние связи и причину отказа.
- `controller-state.json` содержит текущее назначение, его последний результат,
  последний подтверждённый режим и результат локального завершения.
- `source-applied` подтверждает чтение источников политик. `applied` требует
  подтверждения эффективного режима. `blocked` указывает на отказ предварительных
  проверок, `error` — на неуспешную операцию, `overridden` — на локальную отмену
  и проверенную очистку источников. Для обычного `normal` эффективное чтение
  USB в новом входе требуется отдельно.

Администратор завершает экзамен командой
`Start-ScheduledTask -TaskName ExamLab-Local-normal`. Задача сохраняет
отмену известного `examId` перед очисткой под тем же локальным
блокировочным файлом, что используется при применении. Сетевой запрос
выполняется без этой блокировки. Если уже идёт применение машины, локальный
normal ждёт освобождения блокировки до трёх минут. После получения ответа задача
сверяет состояние заново. Повтор отменённого назначения после перезагрузки сохраняет обычный
режим. Новое явное начало получает новую ревизию и новый `examId`. После
частичного сбоя очистки повторите локальный `normal`. Если локальный
`normal` был запущен до получения первого назначения, первый увиденный
`exam` подавляется с `local-normal-baseline-unknown`. Серверный `normal`
до первого экзамена снимает неопределённость.

## Два сигнала готовности

«Можно входить» требует актуальной ревизии и повторного чтения Shared PC,
собственной записи USB в Registry.pol и правил брандмауэра из ActiveStore при текущей
загрузке. Клиент повторяет чтение перед каждым опросом, если успешный
машинный Apply уже записан для этой ревизии. При занятой блокировке, отказе
чтения или отмене он отправляет отрицательный результат готовности в текущем
опросе. Предыдущий результат применения остаётся в локальном состоянии.
Если настройки сохранились после перезагрузки, новый опрос подтвердит их
после повторного чтения. Действие USB из загруженного профиля проверяется
отдельной пользовательской пробой.

«Можно начинать» требует нового подтверждения преподавателя в наблюдаемом
сеансе Guest. Сначала преподаватель открывает плитку Guest и проверяет отказ
доступа к защищённому файлу, работу собственного проекта и готовность
наблюдения Wazuh. На панели он подтверждает эти три проверки для текущего
ПК и сеанса, сопоставляет учебную учётную запись с ПК и даёт команду начинать.
Сопоставление учебной учётной записи остаётся ручным.

Наблюдение Guest для стенда опирается на активный разблокированный сеанс
консоли, SID стандартного локального пользователя из токена Windows и
идентификатор входа AuthenticationId. Имя временной учётной записи должно
совпадать с наблюдавшимся на эталоне шаблоном `shpctac` и пяти строчных
шестнадцатеричных цифр. Событие Security 4720 должно подтверждать создание
этой учётной записи от SYSTEM после загрузки. Если имя меняется в другой
сборке или событие отсутствует, текущий Guest остаётся неподтверждённым.
Клиент передаёт непрозрачный идентификатор, вычисленный из регистрации,
загрузки и текущего входа. Имя и SID остаются на ПК.
[Сеанс консоли](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-wtsgetactiveconsolesessionid) ·
[Токен пользователя](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsqueryusertoken) ·
[Событие создания учётной записи](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4720)

Наблюдение `readiness` привязано к номеру результата в том же опросе.
`bootUtc` содержит время загрузки Windows, `observedUtc` — время пробы.
`machineReady` и `guestSessionId` отражают текущую проверку, причём
`guestSessionId` равен `null` до наблюдения Guest. Наблюдение из последнего
успешного обмена для актуальной ревизии видно в `controller-health.json`.
Поле `GuestObservation` в этом файле фиксирует этап проверки Guest или
причину отсутствия подтверждения.
Смена назначения, загрузки или Guest сбрасывает прежнее подтверждение
сеанса. После потери актуальной связи панель показывает время последнего
подтверждения. Проверьте, что часы стенда и ПК синхронизированы.

В одной проверке на стенде последовательно наблюдайте холодный запуск,
первый Guest, его выход, следующий вход и локальный `normal`. При повторе
назначения после перезагрузки подтверждение Guest требуется заново.
Дождитесь очередного принятого опроса после каждого перехода и сверяйте
ревизию, загрузку, пустой либо изменившийся идентификатор сеанса и обе отметки панели.

## Машинная проба на одноразовой VM

По умолчанию контроллер сообщает `blocked/full-not-ready` на `exam`. Для
замера USB и сетевой политики на подготовленной одноразовой VM можно
передать установщику `-EnableLabControllerPolicyProbe`. До подготовки Shared PC
добавьте в `Network` объект `ControllerEndpoint` с полями `IP` и `Port`.
Например, `{"IP":"192.0.2.10","Port":443}` для контроллера на таком же IP и
порту в HTTPS URL. После подготовки проверяется неизменность `pc.json`.
Перед применением проверяются Shared PC, roster, оба компонента
и отсутствие конфликтов политик. Проба использует адресные действия USB
и Network, сохраняет `FullReady=false`. Если предварительная проверка не прошла,
она повторяется в следующем цикле. При ошибке во время изменения политик
требуется локальный `normal`. Допуск Guest проверяется отдельно.
На рабочих ПК флаг оставляют выключенным.

`controller-policy-probe.json` содержит UTC начала предварительной проверки,
начала машинного применения, USB source readback и Network ActiveStore readback
либо фазу и причину отказа. Действие настроек USB, файлов и сети из Guest
и учебный маршрут проверяются отдельным входом под контролем преподавателя.
Локальный `normal` снимает собственные USB и сетевые ограничения даже при
остановленном сервере.

После попытки очистить политики `normal` вызывает `Disarm` для установленного
окна тревоги и `StopCollection` для выделенного Windows-агента Wazuh. Перед
вызовом проверяются ожидаемые административные пути, права и, для Wazuh,
локальная регистрация и хеш скрипта. `Normal.Collection` в журнале показывает
результаты обоих действий. Ошибка одного действия сохраняет результат другого,
а завершение сбора отмечается отдельно от чтения USB/Network. Если один из
установленных компонентов не завершился, задача возвращает код 1 с отчётом
о выполненных действиях. Повторите локальный `normal` после устранения
причины, указанной в `normal.log`. Повтор назначения отменённого экзамена
сохраняет отмену и сам не повторяет завершение сбора.
