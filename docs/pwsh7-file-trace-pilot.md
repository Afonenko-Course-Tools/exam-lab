# Пилот записи файловых операций

Запись предназначена для отдельного стенда с синтетическими данными. Для
испытания подготовьте отдельный выпуск и используйте одноразовую Windows.
Фактические результаты Windows фиксируйте отдельно от проверок Linux.

## Подготовка выпуска

1. Создайте рядом с базой контроллера закрытый каталог для файловых архивов с
   владельцем процесса контроллера и режимом 0700. Для проверки проводной
   отправки подключите на выделенном TLS-входе
   [фрагмент Nginx](../vm/proxmox/exam-lab-file-trace.nginx.conf.example)
   с точным адресом или подсетью испытательных клиентов.
2. Укажите один и тот же идентификатор, например `file-trace-20261124`, в настройке
   файлового экзамена контроллера и аргументе сборки Windows
   [`--file-trace-exam`](../scripts/build-windows-release.py). Вариант сборки без
   этого аргумента отключает запуск файловой записи.
3. Установите испытательную Windows по [штатному маршруту CMD](pwsh7-pilot-acceptance.md).
   Установщик переносит настройку выпуска в защищённый каталог ExamLab.
   После установки владельцу достаточно доступа к панели TUI.

## Проверка с одного места

1. Войдите в TUI под учётной записью владельца. Отметьте только испытательный ПК
   и назначьте файловый экзамен. После подтверждения машинных политик войдите в
   Guest.
2. Выполните одно контрольное действие в Guest, например прочитайте
   синтетический файл. Windows один раз на ревизию запускает именованный
   WPR FileIO.light в файловом режиме. Основное окно длится 35 секунд. Выход из Guest,
   потеря подтверждённой привязки сеанса или переход в `normal` завершают его
   раньше. Опрашивающая задача продолжает работать, пока отдельный процесс
   выполняет захват и закрывает ETL.
3. Выйдите из Guest. Для короткой пробы без учебной сдачи запустите
   штатный локальный `normal`, затем согласуйте обычный режим кнопкой
   «Обычный» в TUI. При учебной сдаче зарегистрируйте её в TUI до выхода
   из Guest, затем назначьте `normal` в TUI. После закрытия ETL и
   подтверждения очистки `normal` или процесс записи запускает отдельный
   процесс экспорта. Локальный `normal` запускает экспорт и без связи
   с контроллером.
   Он сохраняет ZIP и делает одну попытку отправки при
   подтверждённом физическом Ethernet-маршруте к IP контроллера. Готовность USB
   для обычного пользователя проверяют отдельно. На Wi-Fi,
   виртуальном или неопределённом интерфейсе результат остаётся на ПК.
4. Для локального архива после `normal` войдите в свой административный сеанс
   и выполните `C:\Program Files\ExamLab\Show-ExamLabFileTrace.cmd`.
   Подтвердите UAC. Проводник выделит ZIP в защищённой папке этого
   администратора. Если фоновая операция уже создала ZIP, открывается его
   потоковая локальная копия. Если ZIP ещё отсутствует или задача опроса
   остановлена, команда собирает ZIP из закрытой трассы. Открытие в сеансе
   Guest отклоняется.

Каталог `C:\Program Files\ExamLabSetupReports\ExamLabFileIO-<runId>` содержит
ETL, `wpr.txt`, `metrics.jsonl` и результат фоновой операции `export.json`.
Поле `reportId` подтверждает приём сервером. `export-error.txt` помогает
диагностировать сбой запуска. Приёмник связывает передачу с исторической ревизией
файлового экзамена именно этого зарегистрированного устройства. Повтор с тем же
SHA-256 сохраняет прежний номер. Другой архив той же ревизии отклоняется.
Выгрузки разных мест обрабатываются независимо, пока на сервере хватает места.

## Границы проверки

WPR пишет системные ETW-события в окне Guest. Для анализа сопоставьте время и
процесс, проверьте потери ETW, доступную память и длительность импорта и сборки
IDEA. Поле `sampledPeakUsedPhysicalBytes` показывает наибольшее измеренное
потребление физической памяти всей Windows. В окне записи память измеряется
примерно раз в секунду. По отдельности подтвердите остановку по таймеру, выходу из Guest и
`normal`, отсутствие пауз опроса и сохранность работы пользователя.
Физический кабель и Wi-Fi проверяются по отдельности. Виртуальный сетевой
адаптер в Windows VM даёт локальное сохранение. [Запись WPR в файл](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/logging-mode)

Если процесс захвата аварийно завершился, используйте его точное имя из
закрытой записи `%ProgramData%\ExamLab\file-trace-attempt.json`.

```powershell
wpr -status -instancename ExamLabFileIO-<runId>
wpr -cancel -instancename ExamLabFileIO-<runId>
```
