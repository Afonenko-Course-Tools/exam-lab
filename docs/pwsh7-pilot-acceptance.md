# Сквозная ручная приёмка exam-lab

Испытание рассчитано на два часа на одноразовой Windows x64, 8 ГБ,
с виртуальной флешкой и маршрутом к выделенной VM `10.135.250.231`.
Лист запуска выпуска содержит SHA-256, ссылку на CMD, SSH-профиль владельца
и данные синтетического входа Moodle. Оператор стенда заранее подготавливает
отдельную регистрацию для каждого ПК и открывает выдачу на время прогона.
В аудиторном прогоне один CMD регистрирует до десяти подготовленных ПК.
Повтор с того же ПК использует его собственную регистрацию.

## Замечание по регистрации от 24 ноября

Владелец просит пересмотреть механизм временных окон. На групповом прогоне
одно место и отдельный срок выдачи остановили работу аудитории. В следующей
фазе согласовать постоянный способ допуска заранее подготовленной группы.
Учителю не должно требоваться ручное открытие, продление или переключение
окон во время занятия. Сохранить один CMD, отдельные регистрации ПК и Wazuh,
безопасный повтор установки и отзыв конкретного места. Выдачу десяти мест
до полуночи использовать как временное решение для текущего прогона.

## Замечания по установленным IDEA и JDK от 24 ноября

- Для будущего установщика предусмотреть замену обнаруженной IntelliJ IDEA
  на версию из комплекта ExamLab с явным разрешением оператора на удаление
  конкретного экземпляра. Удалять штатным способом, сохраняя проекты и
  пользовательские настройки. Проверить замену и повтор на Windows VM.
- Сохранять существующие JDK, включая версии, нужные другим приложениям.
  Если подходящего JDK нет, готовить JDK 25 в отдельном защищённом каталоге
  ExamLab. Передавать его путь только экзаменационным IDEA и Gradle, сохраняя
  прежние системные и пользовательские значения `JAVA_HOME`, `PATH` и записи
  прежних установок. Проверить обычный запуск на прежнем JDK и сборку учебного
  проекта на JDK 25 после установки и её повтора.
- В прогоне 24 ноября обнаружен кандидат `C:\Program Files\jdk-26.0.1\bin`.
  Проверка ожидает корневой каталог JDK и ищет в нём `bin\java.exe`, поэтому
  версия кандидата не была определена. Подготовка ПО с отдельным JDK 25
  завершилась с кодом `0`. Следующий сбой возник в `Install-LocalPilot.ps1`.
  После частичной установки повтор остановился на проверке определения
  отключённой задачи `ExamLab-Controller-Poll`. При доработке проверить
  восстановление после ошибки в момент регистрации задач.

## Требования к диагностике следующих прогонов

- Установщик каждого прогона передаёт на выделенный сервер полный комплект
  отладки с идентификатором запуска и версией. В комплект входят промежуточные
  этапы, прогресс загрузок, консольные сообщения, цепочки исключений,
  отчёты дочерних сценариев и относящиеся к сбою журналы Windows и MSI.
  По решению владельца на свой выделенный сервер отправляем собранный комплект
  в сыром виде, включая попавшие в него секреты и персональные данные. Архивы
  хранятся отдельно от Git и каталога публичной раздачи.
- При обрыве связи сохранять комплект локально для повторной отправки.
  Проверять в журнале пилота, что сервер принял материалы, в том числе при
  раннем сбое, частичной установке и повторном запуске.
- При публикации текущего диагностического выпуска обновлять файл по
  штатному адресу `http://10.135.250.231/Start-ExamLab.cmd` и сверять SHA-256
  скачанного файла с листом выпуска.

## Проект принципов после аудиторного прогона 24 ноября

В снимке сервера 34 архива, включая ранние стендовые пробы и несколько отчётов
одного запуска. Отдельно при первом разборе прочитали 15 отчётов с носителя.
Их копии в снимке отсутствуют. Во всех пятнадцати встроенный curl 7.55.1
отклонял параметр ещё до загрузки PowerShell. На Wi-Fi действовал предел
загрузки MSI в 180 секунд. Позднее успешная передача заняла 699 секунд.
Регистрация возвращала в том числе HTTP 403. К концу прогона контроллер выдал
три из десяти мест, первый опрос не пришёл ни от одного из них. В проверенной
ревизии выдача места предшествует загрузке крупных пакетов и проверке ПО.
[Порядок действий в установщике](https://github.com/Afonenko-Course-Tools/exam-lab/blob/6ee99511cfb01b8b0d8385d5623cd20ef96b321a/setup/Install-FromHttps.ps1.in#L298-L373)

Для обсуждения перед исправлениями предлагается следующий порядок.

1. **Обследовать ПК до первого изменения.** Штатными средствами проверить
   сборку и архитектуру Windows, членство в домене, контекст запуска и доступные
   права, службы, существующие задачи, JDK и IDEA, место на диске и возможности
   загрузки. До установки сертификата, PowerShell 7 и регистрации оператор видит
   причины отказа, неизвестные параметры, действия с программами и объём загрузки.
   Недоступное без повышения сведение помечается как непроверенное. Проверка
   через `-WhatIf` годится для команд, которые его поддерживают. Работу MSI,
   SYSTEM-задачи и сеанса Guest подтверждает отдельная проверка после установки.
2. **Подготовить файлы заранее.** `Prefetch` заполняет только кэш пакетами,
   которых не хватает по плану, показывает байты и прогресс, поддерживает докачку
   при поддержке сервера и принимает заранее доставленный комплект. Источник
   доверия для стартового файла оператор получает независимо от скачивания.
   Перед использованием сверяются закреплённые хеши и подписи поставщиков там,
   где они предусмотрены. Готовый кэш позволяет установить локальные компоненты
   без сети. Для первичной регистрации нужна связь с контроллером.
   [Предварительная загрузка в Configuration Manager](https://learn.microsoft.com/en-us/intune/configmgr/osd/deploy-use/configure-precache-content)
3. **Выдавать место при подготовке к экзамену.** Для подготовленной группы
   администратор заранее передаёт приглашение на конкретное место отдельно от общего
   CMD. После проверки плана контроллер закрепляет регистрацию за указанным местом,
   погашает приглашение, выдаёт отдельные ключи контроллера и Wazuh и поддерживает их адресный
   отзыв. Допуск сохраняется при смене IP и долгой загрузке. Проверить, что
   повтор с сохранённым `claim` после потери ответа возвращает ту же регистрацию,
   а попытка занять другое место или использовать отозванное приглашение
   отклоняется. Проверка и загрузка мест не расходуют. В отчёте различаются
   неизвестный ПК, отказ в доступе, исчерпание мест и недоступность сервера.
4. **Применять и проверять один план.** Один CMD данного выпуска вызывает
   существующие модули. За обнаружение и изменение каждого компонента отвечает
   один модуль, общий для обычного и диагностического запуска. Перед изменением
   он перепроверяет соответствующие условия, после него проверяет результат в
   целевом контексте. Восстанавливает только подтверждённо свою задачу. При чужой
   задаче или сомнении во владельце показывает различия по полям и останавливается.
   При сбое установщик отменяет системные изменения этой попытки в обратном
   порядке. Для затронутой настройки, задачи или политики он сохраняет прежнее
   значение, для нового ресурса — факт создания. После прерывания следующий
   запуск завершает отмену. Ранее работающий локальный `normal` остаётся доступен.
   Успешно подготовленные приложения и кэш повторно используются. Целостность
   пакета проверяется при доставке, установленное ПО — по версии и работе.
   Первичная ошибка `Install-LocalPilot` и конкретное поле
   `ExamLab-Controller-Poll`, отклонённое при повторе, остались неизвестны.
   Критерий исправления — выделенный сервер принимает за один проблемный прогон
   запись первичной ошибки дочернего шага и ожидаемые и фактические поля задачи,
   с версией и номером попытки. До регистрации доверенный адрес
   принимает только архив диагностики, без выдачи места или ключей. Если доверие
   к адресу ещё не установлено или сервер недоступен, архив остаётся локально
   до подтверждения доставки. [Требования и проверка результата установки Win32](https://learn.microsoft.com/en-us/intune/app-management/deployment/add-win32)
5. **Расширять пилот по результатам.** Сначала на VM проверить частичную
   установку и повтор. Затем на одном согласованном выделенном физическом ПК
   оператор может дать агенту временный WinRM или SSH с отдельной учётной записью
   и доступом с машины оператора. Начать с чтения задачи и журналов. Удалённую
   сессию завершить и временный доступ отозвать. Штатное управление сохраняет
   исходящий опрос. До расширения на группу независимый оператор проверяет
   первый опрос, реальный Guest, IDEA и сдачу, локальный `normal` без сети и
   обычный вход с прежним проектом.

### Альтернатива для отладки без мест

Предлагается включать свободную регистрацию на выделенном пилотном сервере.
Оператор один раз выбирает этот вариант для стенда. Любой новый тестовый ПК
с доступом к его внутреннему адресу может использовать общий CMD. Для этого
не нужны список ПК или IP, приглашение, свободное место, срок выдачи либо
подтверждение преподавателя на каждую попытку.

- Обследование, предварительная загрузка, локальные шаги установки и отправка
  сырого архива выполняются с нулём заведённых мест. Для разбора раннего
  отказа достаточно версии выпуска и идентификатора запуска. Используется уже
  имеющийся `POST /install/diagnostics`, который возвращает номер принятого
  архива. При приёмке проверить отправку полного сырого комплекта с реального
  ПК с учётом лимитов запроса и хранилища. Тестовому ПК
  доступна отправка, чтение накопленных архивов остаётся у оператора.
- Когда проверяется опрос контроллера или Wazuh, стенд автоматически выдаёт
  этому ПК собственную тестовую регистрацию для нужной службы. Повтор с тем же
  сохранённым `claim` возвращает ту же регистрацию, включая случай потери
  первого ответа. Два ПК за одним IP получают разные регистрации. Имеющиеся
  обработчики установки и опроса остаются общими для обоих вариантов.
- Диагностический запуск на новом ПК проходит в обычном режиме.
  Экзамен назначает оператор отдельно. Для интерактивной работы на выбранном
  ПК предусмотрен отдельный диагностический скрипт подготовки SSH или WinRM.
  Его запускает локальный администратор, доступ сохраняется при откате ExamLab.

Критерий приёмки варианта — на стенде с нулём мест два незнакомых ПК начинают
прогон без действий преподавателя. Архив раннего сбоя первого поступает на
сервер ещё до регистрации. Второй доходит до первого опроса, затем меняет
IP и повторяет запуск. В панели остаётся одна запись этого ПК. Выдача
экзаменационного места и применение экзаменационных политик проверяются отдельно.

## Установка и повтор

1. Войдите в обычную учётную запись администратора Windows. На свежем образе
   завершите первоначальную настройку и перезагрузите ПК.
2. Откройте в Edge `http://10.135.250.231/Start-ExamLab.cmd` и сохраните файл.
   Если Edge попросит подтвердить сохранение, нажмите «Сохранить».
   В обычной командной строке проверьте его SHA-256.

   ```cmd
   certutil -hashfile "%USERPROFILE%\Downloads\Start-ExamLab.cmd" SHA256
   ```

   Сверьте все 64 символа со значением из листа выпуска. При совпадении
   откройте скачанный CMD и подтвердите UAC. CMD устанавливает сертификат,
   получает PowerShell 7 и запускает проверенный установщик по HTTPS.
   Регистрация контроллера и Wazuh проходит автоматически. Если система попросит
   перезапуск, перезапустите Windows и откройте тот же проверенный файл.
3. Дождитесь сообщения об успешном завершении. Повторите запуск тем же CMD.
   В панель должен прийти свежий итоговый отчёт той же версии. В Windows
   должна остаться одна запись ExamLab. При ошибке сохраните выведенный номер
   отчёта. Если сеть недоступна, окно покажет путь к локальному архиву.

## Аварийный локальный normal

Выйдите из Guest. Войдите в обычную административную учётную запись Windows,
оставив сеть до сервера отключённой. В командной строке от имени администратора
запустите установленное задание.

```cmd
schtasks /Run /TN ExamLab-Local-normal
```

Дождитесь завершения задания. Выйдите и заново войдите в обычную учётную
запись. Переподключите виртуальную флешку, откройте обычный файл и прежний
проект. После восстановления связи проверьте, что старое назначение
не возвращает экзаменационный режим.

## Экзамен с записью файлов

1. В TUI владельца нажмите «Экзамен с записью файлов» или `F2` и проверьте
   название открытого экзамена. Выберите ПК, нажмите «Экзамен» и подтвердите
   назначение. Дождитесь допуска машины.
2. Войдите в новый Guest. В его каталоге создайте, откройте и переименуйте
   синтетический файл. Запись стартует для этого Guest и автоматически
   останавливается по таймеру или при завершении режима. На ПК с 8 ГБ при
   параллельной работе IDEA фиксируйте пиковую память и потери событий ETW.
3. Выйдите из Guest. Для короткой пробы запустите локальный `normal` по
   инструкции выше. Дождитесь отметки о локальном снятии в TUI и нажмите
   «Обычный». Если сервер доступен по Ethernet, проверьте поступление архива на стенд.
   При подключении только по Wi-Fi войдите в обычную административную учётную
   запись и откройте `C:\Program Files\ExamLab\Show-ExamLabFileTrace.cmd`. Скопируйте
   архив из открывшегося Проводника на диск. Оставьте исходный архив на ПК до
   проверки копии. В журнале приёмки укажите фактически проверенный тип связи.
