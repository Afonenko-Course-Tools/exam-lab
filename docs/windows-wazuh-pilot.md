# Подготовка Windows-агента Wazuh для локального пилота

Шаг выполняется в повышенном PowerShell 7 x64. Используйте
административный комплект из проверенной копии exam-lab и проверенный адрес
менеджера испытательного сегмента. Для связки нужен Wazuh Manager 4.14.10
с правилом `110610` и локальной реакцией `exam-lab-alert.cmd`. Внешний порт
регистрации менеджера не требуется.
[Конфигурация Deployment](https://github.com/Afonenko-Course-Tools/prairielearn-deployment/pull/9)

Подготовьте официальный `wazuh-agent-4.14.10-1.msi` и один ключ, экспортированный
менеджером через `manage_agents -e`. Держите ключ в закрытом локальном файле,
доступном администратору. Сценарий проверит SHA-512 MSI, действительность
подписи `Wazuh, Inc` и наличие сторонней установки. Указанный путь к файлу
ключа допустимо передать аргументом. Содержимое ключа читается и записывается
в защищённый `client.keys` внутри процесса PowerShell. Локальный файл ключа
администратор удаляет после подтверждения регистрации и проверки повтора.

```powershell
& .\setup\Install-ExamLabWazuh.ps1 -Action Install `
    -MsiPath $wazuhMsi -ManagerIPv4 $managerAddress -AgentKeyPath $privateKeyFile
```

Установщик проверяет конфликты с Wazuh и OSSEC. В защищённом
`HKLM:\SOFTWARE\ExamLabWazuhPilot` он сохраняет `ProductCode` из подписанного
MSI и сведения о начале подготовки. В фазе `Preparing` повтор с тем же
пакетом, менеджером и регистрацией продолжает подготовку после проверки
Windows Installer. При конфликте повтор возвращает причину и сохраняет
состояние для администратора. Успешный запуск оставляет службу в ручном
режиме, готовой к началу экзамена. Сбор начинается с `exam`.

Агент использует ручной старт и отправляет только новые записи `Application`
поставщика `ExamLab-Alert` с Event ID `6101` и уровнем `Warning`. Проверка
целостности файлов, инвентаризация, Rootcheck, SCA, конфигурация агента из группы
менеджера и автоматическая регистрация отключены. Подтверждение преподавателя
хранится локально в защищённом `LastAcknowledgement` компонента оповещения.
Пользовательский экран и его первичная инициализация описаны в
[инструкции оповещения](windows-alert.md).

Унаследованные права Windows Modules Installer (`TrustedInstaller`) учитываются
при проверке каталога и сценария оповещения в Program Files. Поддерживаемые
переходы с `eec71eb` и `cffdf33` сверяют старый хеш, установленный продукт,
менеджер и ключ. Повтор заменяет сценарий при остановленной службе и сохраняет
существующую регистрацию.

Для локальной пробы после подготовки экрана запустите и затем остановите
сбор установленным сценарием. Успешная остановка подтверждает `Stopped` и
`Manual` через диспетчер служб Windows. Локальный `normal` с интеграцией
Wazuh вызывает эту же остановку после снятия экзаменационных ограничений.

```powershell
$wazuhSetup = Join-Path $env:ProgramFiles 'ExamLabWazuh\Install-ExamLabWazuh.ps1'
pwsh.exe -NoProfile -ExecutionPolicy Bypass -File $wazuhSetup -Action StartCollection
# Проведите контрольную пробу на VM.
pwsh.exe -NoProfile -ExecutionPolicy Bypass -File $wazuhSetup -Action StopCollection
```

После старта подтвердите связь выделенного агента на менеджере. Одна новая
Windows-запись должна дать одну тревогу `110610` с тем же номером записи.
[Проверка тревоги через TUI](../vm/proxmox/wazuh/README.md#контрольная-проба-через-tui)

После проверенного локального `normal` штатное удаление ExamLab вызывает
выделенный сценарий. Он сверяет `ProductCode`, состояние службы и файлы перед
вызовом Windows Installer. Wazuh MSI может оставить сохранённые настройки и
ключ под именами `*.save`. Сценарий сверяет их хеши перед удалением и сообщает
об оставшемся каталоге. При окончательном выводе ПК оператор менеджера отзывает
тестовый ключ.
[Штатные действия MSI Wazuh 4.14.10](https://raw.githubusercontent.com/wazuh/wazuh/v4.14.10/src/win32/RemoveAllScript.vbs)
[Импорт ключа и проверка связи](https://documentation.wazuh.com/current/user-manual/agent/agent-enrollment/enrollment-methods/via-manager-API/importing-the-key.html)
