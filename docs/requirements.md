# Требования к экзаменационной среде Windows

Согласованный объём, уточнённый 16 ноября 2026 года. Требования описывают целевое поведение;
конкретные механизмы проходят пилот до внедрения в аудитории.

## Локальные файлы и заранее подготовленные подсказки

Guest должен работать со своим чистым профилем и необходимыми файлами Windows,
IDEA, JDK и Git. Требуется широкое ограничение чтения пользовательских данных
вне его профиля, чтобы затруднить использование подсказок, заранее оставленных
через обычную учётную запись. Проверяются другие профили и общие места для
данных. Поведение раздельно проверяется в Explorer, диалоге IDEA и Java;
скрытие диска в Explorer само по себе не подтверждает запрет файлового API.

По уточнению владельца это практическая защита, а не полная гарантия изоляции.
Подмена студентом системных файлов исключена из модели угроз. Политика строится
на широком разделении системных файлов, программ и пользовательских данных;
хрупкие разрешительные или запретительные списки частных путей, мешающие
обычной работе из-за неполноты, не допускаются. Возможность понижения целостности
сеанса (MIC) исследуется; низкая целостность сама по себе ограничивает запись,
но не запрещает чтение. Необходимость `NoReadUp` и совместимость приложений
проверяются отдельно.

Уточнение 16 ноября: приоритет — достаточно широкое и простое ограничение,
строгость которого может быть умеренной. Сначала проверяются близкие штатные
варианты, прежде чем добавлять новые слои изоляции. Для каждого кандидата
раздельно фиксируются навигация Explorer, диалог IDEA и прямое чтение из Java.
Ограничение интерфейса можно рассматривать как практический вариант, но оно
не объявляется запретом файлового API. Выбор делается по фактическим результатам;
пользовательские списки исключений программ не заменяют широкое правило.

Уточнение владельца о широкой области: ограничить доступ к дискам кроме C:, а на C:
оставить необходимые системные каталоги, программы и собственный чистый профиль
для учебной работы. Эти крупные категории не считаются списком исключений
отдельных приложений. Для первого практического барьера допустимо затруднение
поиска заранее оставленных подсказок; доступ по известному полному пути должен
проверяться и явно отражаться как обход, если он остаётся.

После отрицательных проб ограничения навигации владелец выбрал продолжать
поиск готового изолятора для запрета чтения вне системных каталогов, даже если
это задержит первый пилот. Скрытие дисков и запрет просмотра родительских папок
не заменяют этот результат; работа собственного проекта IDEA должна сохраняться
после закрытия и повторного открытия.

Последнее уточнение: допустим только инструмент с открытым исходным кодом либо
небольшой сценарий поверх готовых механизмов Windows. Проприетарные изоляторы
исключены. Владелец прямо разрешил рекурсивно менять ACL файлов для запрета
нашему Guest, если это не нарушает типовые занятия обычной учётки. Прежний
запрет массовой ACL-обработки в этой части отменён. Это не разрешение сбрасывать
все DACL, менять владельцев или снимать чужие ACE; Normal удаляет только свои
точные правила из текущего состояния, без снимка и обратного импорта.

Адресный DENY чтения файлов текущему Guest SID и conditional ACE с группой
исключения ordinary — исследованные кандидаты, не принятые реализации. Пока
не доказаны сохранность обычных прав, работа IDEA после повторного открытия,
доставка следующему Guest, обработка новых файлов и момент допуска к работе.
Подробности и первичные источники — в [обзоре вариантов](file-isolation-options-2026-11-16.md).
До подтверждения широкого механизма локальное файловое ограничение не выполнено.

Текущий этап по прямому поручению владельца ограничен интернет-поиском,
документированием и коммитом результатов. Новые испытания и запуски VM остановлены;
разрешение исследовать рекурсивные ACL не отменяет эту остановку.

## Экзаменационный сеанс

| Область | Требование |
| --- | --- |
| Рабочие ПК | Используется существующая Windows 10; точные редакция и сборка устанавливаются перед пилотом. |
| Подготовка | Основной результат — воспроизводимый инструмент установки и подготовки существующей Windows. Он проверяет совместимость и существующее ПО, поддерживает безопасный повтор и сообщает фактический результат. VM служит стендом; разовые диагностические сценарии не заменяют этот инструмент. |
| Учётная запись | Студент работает в отдельном гостевом сеансе без административных прав. Целевой штатный механизм — Shared PC Guest. Обычная постоянная учётка с именем Guest не считается эквивалентом. |
| Очистка | После выхода из Windows временные гостевые данные удаляются; следующий студент получает чистую среду без ручного сброса между студентами. |
| Инструменты | IDEA, JDK и Git устанавливаются администратором для всех пользователей. Компиляция, запуск и отладка Java выполняются локально. |
| Учебный объём | Первый вариант обслуживает Core Java и Git без внешних Java-библиотек и загрузки зависимостей во время экзамена. |
| Помощь IDE | Обычные дополнения кода, инспекции и рефакторинг доступны; генеративные помощники, локальные и облачные, исключаются. |
| Локальные данные | Экзаменационный пользователь не получает доступ к сохранённым работам и подсказкам других пользователей. Обычные учебные данные сохраняются. |
| Флешки | Студент не может прочитать принесённые подсказки с флешки, в том числе средствами IDEA или собственной Java-программы. |

Глобальная заморозка установки всех устройств не требуется. Первый кандидат
для флешек — пользовательская политика запрета чтения съёмных дисков.
Её применение к каждому новому Shared PC Guest и фактическое вступление в силу
нужно проверить на выбранной Windows. Охват телефонов, внешних SSD с другой
классификацией и иных носителей уточняется отдельно; он не подменяет проверку флешек.

## Сеть во время экзамена

Сетевые ограничения обязательны. Доступны только согласованные PrairieLearn,
университетский Moodle `https://edurfe.bsu.by/` и необходимые технические соединения.
Запрет остальных направлений действует для браузера, IDEA, Git и программ студента.
Браузерный список сайтов сам по себе этому требованию не соответствует.

| Часть списка разрешений | Правило включения |
| --- | --- |
| PrairieLearn | Конкретный согласованный экземпляр и необходимые для экзамена обращения. |
| Moodle | `edurfe.bsu.by` и подтверждённые зависимости входа и работы с нужным заданием. |
| Управление | Связь с контроллером в объёме опроса и отправки результата. |
| Служебная сеть | Необходимые DNS/DHCP и другие подтверждённые системные обращения с ограничением назначения. |

Для каждого дополнительного назначения указывается его цель. Не разрешается
автоматически целый университетский диапазон, доменное семейство или весь CDN
из-за одного обнаруженного обращения. Список не расширяется автоматически по
браузерной истории. Доступность других материалов внутри Moodle и PrairieLearn
определяется также настройками экзамена и правами в этих системах.

На публичной странице Moodle 15 ноября 2026 года обнаружены форма входа на том же
сайте и ссылки на ресурсы `www.googletagmanager.com` и `fonts.googleapis.com`.
Это не подтверждённые обязательные зависимости: сначала проверяется работа с их
блокировкой. Внешний SSO на открытой странице не обнаружен; успешный вход и маршрут
до сдачи ещё требуют проверки. Серверные обращения Moodle к LDAP или обмен оценками
не открываются ученическим ПК только на основании их наличия на сервере.

## Обычные занятия и отказы

Обычные учётные записи, проекты, программы, сеть и флешки должны работать вне
экзамена независимо от доступности контроллера. Перезагрузка не является
обязательным способом восстановления; она допустима для конкретной проверенной настройки.

1. Ошибка опроса, неверный ответ и отсутствие сервера не меняют конфигурацию.
2. Потеря связи во время экзамена сама по себе не снимает ограничения.
3. Завершение экзамена и переход к обычной работе доступны преподавателю или
   администратору локально без обязательного ответа сервера. Guest не может снять
   ограничения или изменить управляющие сценарии. Выход Guest очищает его профиль
   и сам по себе не завершает экзаменационный режим для следующих студентов.
4. Частичный отказ применения настроек не должен оставлять ПК непригодным
   для следующего занятия. Локальный переключатель снимает собственные ограничения
   и проверяет обычный режим; чужие политики не затираются.
5. Локальное завершение не отменяется следующим получением прежнего серверного
   состояния `exam`: требуется новое явное начало экзамена.

Гостевые настройки изолируются от обычных пользователей, где это подтверждено.
SharedPC, общая политика firewall, правила установки устройств и общие ACL могут
затрагивать весь компьютер; удаление профиля не считается их восстановлением.
Экзаменационные настройки не записываются в общий шаблон всех будущих профилей.
Отключение или ограничение обычных учёток не оставляется постоянным последствием.

По уточнению владельца Shared PC допускается включить один раз при подготовке
и оставить включённым, если реальные проверки подтвердят сохранность обычных
сценариев работы. В этом целевом договоре завершение экзамена снимает его
ограничения, сохраняя принятую подготовку; полная административная отмена
подготовки выполняется отдельно. До приёмки нужны обычный вход, проекты,
USB, сеть и перезагрузка при включённом Shared PC. Это разрешённое направление
упрощения, а не утверждение, что текущий переключатель уже его реализует.

По следующему прямому указанию владельца экзаменационный переключатель работает
без снимков Windows и без полного обратного импорта firewall, GPO или реестра.
Используются явные скриптовые настройки обычного и экзаменационного режимов.
Чужая настройка в управляемом пути является конфликтом для предварительной
проверки; переключатель не присваивает себе всю подсистему. Минимальная запись
режима и идентификатора запуска не содержит копию настроек Windows. Тестовые
копии VM и резервирование данных серверной миграции имеют отдельное назначение.

Сценарии поломки оборудования, отключения питания и действия пользователя
с административными правами не входят в первый пилот.

## Управление

Во время экзамена требуется связывать подтверждённую учебную личность студента
с зарегистрированным компьютером класса и конкретным экзаменационным запуском.
Для выбранного экзамена должно быть возможно запрещать входы извне класса,
а несовпадение ожидаемой пары студент/ПК, параллельные входы и смену учётной
записи — блокировать либо явно показывать преподавателю согласно выбранному
режиму контроля. Обычный внешний доступ к курсам вне экзамена сохраняется.

Учётка Moodle/PrairieLearn и локальная учётка Windows различаются. IP подтверждает
сетевой источник, но не личность студента и не Windows-сеанс. Имена или заголовки,
переданные браузером, не считаются доверенным подтверждением. Способ проверки
компьютера и допустимого Windows-сеанса выбирается на стандартных механизмах;
сейчас он не реализован. Настройки входа не меняют оценки, курс или LTI-личность.

Для экзаменационного входа переиспользуется существующий проверенный LTI
callback. Предпочтительное расширение — отдельный элемент Moodle «Экзамен»
в той же регистрации; обычный вход сохраняется. Имя используется для показа,
а связь хранится по устойчивой проверенной идентичности, не по совпадению имён.
Подписанный контекст элемента связывается с экзаменом на сервере. Создание новой
регистрации или экземпляра курса не требуется само по себе. У текущего Gateway
проверка нескольких элементов уже есть, но передача экзаменационного контекста
в сессию PrairieLearn и контроль последующих API/WebSocket обращений ещё
предстоят; одна проверка callback не закрывает старую открытую сессию.

Контроллер — Linux VM в Proxmox с постоянным адресом. Аудиторные Windows-ПК
работают по DHCP, первоначально регистрируются и далее сами опрашивают контроллер.
Идентичность ПК не определяется текущим IP; собственный поиск машин в сети не нужен.

На Windows используются локально установленные сценарии и штатный планировщик.
Опрос передаёт данные управления экзаменом и результаты; он не скачивает новые
сценарии, пакеты и произвольные команды. Обновление кода и политик выполняется
редкой отдельной административной операцией.

Контроллер различает запрошенное состояние, последний подтверждённый результат
и отсутствие актуальной связи. Успешная запись локального флага не заменяет
проверку фактических ограничений. Механизм доверия ответам контроллера выбирается
на стандартных средствах до включения удалённого управления.

## Проверка и границы проекта

Первую эталонную Windows VM создаёт и настраивает агент при старте исполнения
на другом ноутбуке, используя доступный официальный образ или ISO. Заранее
установленная пользователем Windows не требуется. Разовая ручная помощь допустима
при необходимости, включая требуемый вход владельца или подтверждение лицензии.
Повторные испытания конфигураций автоматизируются. После существенных изменений
соответствующей части проводится короткая ручная проверка Guest, IDEA, входа в Moodle
и реальных USB. Для первого варианта проверяется одна комбинация Windows и программ.

Инструмент подготовки должен работать по проверяемым возможностям Windows,
а не только на одной зафиксированной сборке эталона. Предпосылки выбранных
программ, пригодность редакции для Shared PC и фактически испытанные комбинации
указываются раздельно. Поддержка широкого диапазона версий подтверждается
испытаниями; успешная проверка номера версии сама по себе этого не доказывает.

Все целевые системы x64. Установка запускается с повышенными правами администратора. До установки
и изменения настроек проверяются минимальные версии, редакция, разрядность,
PowerShell и необходимые механизмы групповых политик, Shared PC, firewall
и планировщика. Целевая Windows русскоязычная: вызовы используют SID,
внутренние идентификаторы и системные пути, поддерживают кириллицу и пробелы.
Испытание путей с кириллицей на английской ОС не заменяет проверку русской Windows.

Проект состоит из небольшого числа конфигураций и обвязок готовых инструментов.
Собственные пакетные менеджеры, форматы блокировки зависимостей, универсальные
оркестраторы, системы автоматического обновления и протоколы доказательств не создаются.

Конфигурация серверных сервисов, локального стенда и VM сохраняется в Git
с единым владельцем развёртывания. Курсы и платформа должны развиваться
независимо; варианты организации репозиториев рассматриваются в
[плане](work-plan.md#предложение-по-общей-конфигурации-платформы-и-стенда).
Секреты, установщики и рабочие данные не входят в Git; их размещение,
резервное копирование и восстановление должны воспроизводиться по конфигурации.

## Минимальная приёмка

| Сценарий | Ожидаемый результат |
| --- | --- |
| Флешка в настоящем Guest | Чтение запрещено для новой, ранее использованной и заранее вставленной флешки; проверены Explorer, IDEA и Java. |
| Разрешённая сеть | В чистом браузере проходят вход, получение задания, необходимые переходы и сдача в Moodle и PrairieLearn. |
| Запрещённая сеть | Соединения к посторонним назначениям блокируются из браузера и Java; проверены используемые IPv4/IPv6 и прекращение обмена по соединению, открытому до включения ограничений. |
| Следующий студент | После выхода из Windows новый Guest получает чистую среду; обычные профили и файлы сохранены. |
| Завершение без сервера | Экзамен завершается локально, затем обычный пользователь работает с сетью, флешкой и прежними проектами. |
| Полномочия Guest | Гость не может вызвать завершение режима, изменить политики или управляющие сценарии; преподаватель/администратор может завершить экзамен без сервера. |
| Ошибки и повторы | Ошибочный опрос ничего не меняет; повторное применение и завершение безопасны; старый `exam` не включает ограничения вновь. |
| Частичный отказ | Локальный переключатель снимает собственные ограничения и проверяет обычный режим; чужие настройки сохраняются, контроллер не требуется. |

Проверки с подменёнными API, разбор синтаксиса и CI на другой Windows не заменяют
эти испытания на целевом образе и реальном гостевом сеансе.
