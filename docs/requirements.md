# Требования к экзаменационной среде Windows

Согласованный объём на 15 ноября 2026 года. Требования описывают целевое поведение;
конкретные механизмы проходят пилот до внедрения в аудитории.

## Экзаменационный сеанс

| Область | Требование |
| --- | --- |
| Рабочие ПК | Используется существующая Windows 10; точные редакция и сборка устанавливаются перед пилотом. |
| Учётная запись | Студент работает в отдельном гостевом сеансе без административных прав. Целевой штатный механизм — Shared PC Guest. Обычная постоянная учётка с именем Guest не считается эквивалентом. |
| Очистка | После выхода из Windows временные гостевые данные удаляются; следующий студент получает чистую среду без ручного сброса между студентами. |
| Инструменты | IDEA, JDK и Git устанавливаются администратором для всех пользователей. Компиляция, запуск и отладка Java выполняются локально. |
| Учебный объём | Первый вариант обслуживает Core Java и Git без внешних Java-библиотек и загрузки зависимостей во время экзамена. |
| Помощь IDE | Обычные дополнения кода, инспекции и рефакторинг доступны; генеративные помощники, локальные и облачные, исключаются. |
| Локальные данные | Экзаменационный пользователь не получает доступ к сохранённым работам и подсказкам других пользователей. Обычные учебные данные сохраняются. |
| Флешки | Студент не может прочитать принесённые подсказки с флешки, в том числе средствами IDEA или собственной Java-программы. |

Глобальная заморозка установки всех устройств не требуется. Первый кандидат
для флешек — пользовательская политика запрета чтения съёмных дисков.
Её применение к каждому новому Shared PC Guest и фактическое вступление в силу
нужно проверить на выбранной Windows. Охват телефонов, внешних SSD с другой
классификацией и иных носителей уточняется отдельно; он не подменяет проверку флешек.

## Сеть во время экзамена

Сетевые ограничения обязательны. Доступны только согласованные PrairieLearn,
университетский Moodle `https://edurfe.bsu.by/` и необходимые технические соединения.
Запрет остальных направлений действует для браузера, IDEA, Git и программ студента.
Браузерный список сайтов сам по себе этому требованию не соответствует.

| Часть списка разрешений | Правило включения |
| --- | --- |
| PrairieLearn | Конкретный согласованный экземпляр и необходимые для экзамена обращения. |
| Moodle | `edurfe.bsu.by` и подтверждённые зависимости входа и работы с нужным заданием. |
| Управление | Связь с контроллером в объёме опроса и отправки результата. |
| Служебная сеть | Необходимые DNS/DHCP и другие подтверждённые системные обращения с ограничением назначения. |

Для каждого дополнительного назначения указывается его цель. Не разрешается
автоматически целый университетский диапазон, доменное семейство или весь CDN
из-за одного обнаруженного обращения. Список не расширяется автоматически по
браузерной истории. Доступность других материалов внутри Moodle и PrairieLearn
определяется также настройками экзамена и правами в этих системах.

На публичной странице Moodle 15 ноября 2026 года обнаружены форма входа на том же
сайте и ссылки на ресурсы `www.googletagmanager.com` и `fonts.googleapis.com`.
Это не подтверждённые обязательные зависимости: сначала проверяется работа с их
блокировкой. Внешний SSO на открытой странице не обнаружен; успешный вход и маршрут
до сдачи ещё требуют проверки. Серверные обращения Moodle к LDAP или обмен оценками
не открываются ученическим ПК только на основании их наличия на сервере.

## Обычные занятия и отказы

Обычные учётные записи, проекты, программы, сеть и флешки должны работать вне
экзамена независимо от доступности контроллера. Перезагрузка не является
обязательным способом восстановления; она допустима для конкретной проверенной настройки.

1. Ошибка опроса, неверный ответ и отсутствие сервера не меняют конфигурацию.
2. Потеря связи во время экзамена сама по себе не снимает ограничения.
3. Завершение экзамена и переход к обычной работе доступны преподавателю или
   администратору локально без обязательного ответа сервера. Guest не может снять
   ограничения или изменить управляющие сценарии. Выход Guest очищает его профиль
   и сам по себе не завершает экзаменационный режим для следующих студентов.
4. Частичный отказ применения настроек не должен оставлять ПК непригодным
   для следующего занятия. Восстанавливаются исходные значения изменённых настроек.
5. Локальное завершение не отменяется следующим получением прежнего серверного
   состояния `exam`: требуется новое явное начало экзамена.

Гостевые настройки изолируются от обычных пользователей, где это подтверждено.
SharedPC, общая политика firewall, правила установки устройств и общие ACL могут
затрагивать весь компьютер; удаление профиля не считается их восстановлением.
Экзаменационные настройки не записываются в общий шаблон всех будущих профилей.
Отключение или ограничение обычных учёток не оставляется постоянным последствием.

Сценарии поломки оборудования, отключения питания и действия пользователя
с административными правами не входят в первый пилот.

## Управление

Контроллер — Linux VM в Proxmox с постоянным адресом. Аудиторные Windows-ПК
работают по DHCP, первоначально регистрируются и далее сами опрашивают контроллер.
Идентичность ПК не определяется текущим IP; собственный поиск машин в сети не нужен.

На Windows используются локально установленные сценарии и штатный планировщик.
Опрос передаёт данные управления экзаменом и результаты; он не скачивает новые
сценарии, пакеты и произвольные команды. Обновление кода и политик выполняется
редкой отдельной административной операцией.

Контроллер различает запрошенное состояние, последний подтверждённый результат
и отсутствие актуальной связи. Успешная запись локального флага не заменяет
проверку фактических ограничений. Механизм доверия ответам контроллера выбирается
на стандартных средствах до включения удалённого управления.

## Проверка и границы проекта

Первую эталонную Windows VM создаёт и настраивает агент при старте исполнения
на другом ноутбуке, используя доступный официальный образ или ISO. Заранее
установленная пользователем Windows не требуется. Разовая ручная помощь допустима
при необходимости, включая требуемый вход владельца или подтверждение лицензии.
Повторные испытания конфигураций автоматизируются. После существенных изменений
соответствующей части проводится короткая ручная проверка Guest, IDEA, входа в Moodle
и реальных USB. Для первого варианта проверяется одна комбинация Windows и программ.

Проект состоит из небольшого числа конфигураций и обвязок готовых инструментов.
Собственные пакетные менеджеры, форматы блокировки зависимостей, универсальные
оркестраторы, системы автоматического обновления и протоколы доказательств не создаются.

## Минимальная приёмка

| Сценарий | Ожидаемый результат |
| --- | --- |
| Флешка в настоящем Guest | Чтение запрещено для новой, ранее использованной и заранее вставленной флешки; проверены Explorer, IDEA и Java. |
| Разрешённая сеть | В чистом браузере проходят вход, получение задания, необходимые переходы и сдача в Moodle и PrairieLearn. |
| Запрещённая сеть | Соединения к посторонним назначениям блокируются из браузера и Java; проверены используемые IPv4/IPv6 и прекращение обмена по соединению, открытому до включения ограничений. |
| Следующий студент | После выхода из Windows новый Guest получает чистую среду; обычные профили и файлы сохранены. |
| Завершение без сервера | Экзамен завершается локально, затем обычный пользователь работает с сетью, флешкой и прежними проектами. |
| Полномочия Guest | Гость не может вызвать завершение режима, изменить политики или управляющие сценарии; преподаватель/администратор может завершить экзамен без сервера. |
| Ошибки и повторы | Ошибочный опрос ничего не меняет; повторное применение и завершение безопасны; старый `exam` не включает ограничения вновь. |
| Частичный отказ | Локальное восстановление возвращает изменённые параметры; следующему обычному занятию не требуется контроллер. |

Проверки с подменёнными API, разбор синтаксиса и CI на другой Windows не заменяют
эти испытания на целевом образе и реальном гостевом сеансе.
