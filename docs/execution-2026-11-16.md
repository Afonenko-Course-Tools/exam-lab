Продолжается локальный пилот из ветки `codex/windows-local-pilot`.
Исходное состояние сохранено в `f21b082`; рабочее дерево в начале сессии чистое.
Результаты 15 ноября и их границы находятся в [предыдущем отчёте](execution-2026-11-15.md).
Полный `exam` остаётся заблокированным, `FullReady=false`.

## Уточнение задачи и архитектурная ревизия

Владелец уточнил: файловое ограничение должно быть широким и простым,
строгость может быть умеренной; нужно проверять близкие варианты. Поэтому
следующий шаг — штатный Shared PC `RestrictLocalStorage`, отдельно от отладки
Sandboxie и массовой переметки файлов. Списки исключений отдельных программ,
новые launchers и собственный механизм изоляции не добавляются.

Microsoft описывает `RestrictLocalStorage` как ограничение просмотра и сохранения
локальных данных через File Explorer. Свойство
[`ShouldAvoidLocalStorage`](https://learn.microsoft.com/en-us/uwp/api/windows.system.profile.sharedmodesettings.shouldavoidlocalstorage)
сообщает приложениям о необходимости скрыть точки доступа; Downloads, removable
и mapped drives описаны как исключения. Это описание интерфейса, а не доказанный
запрет Java API. Для canary планируется сравнить Explorer, IDEA File Open и Java
на известных контрольных файлах, сохранить работу JDK и собственного workspace,
затем проверить обычную учётку после снятия ограничения. По
[CSP SharedPC](https://learn.microsoft.com/en-us/windows/client-management/mdm/sharedpc-csp#restrictlocalstorage)
политика задаётся до включения Shared PC, поэтому используется свежая копия эталона.

Соседний простой вариант — пользовательская `NoViewOnDrive`: Microsoft явно
[не обещает запрета другим программам](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-windowsexplorer#noviewondrive).
Его следует оценивать как ограничение интерфейса, включая возможную помеху своему
workspace. MIC Low без объектного NR уже позволил чтение; массовая установка NR
не выбрана. Sandboxie сохраняется как отдельный кандидат после двух отрицательных
проб; продолжение COM-диагностики не является первым шагом по новому приоритету.

  подмены Thread UI и изменения языковых списков. Результат пары приведён ниже.
- Общий Guest USB/network: независимо проверен план с прямыми публичными
  компонентами, временными CU CA/proxy и локальным GUI-вызовом исходной SYSTEM
  normal-задачи. До USB Apply все nonadmin-профили должны быть выгружены;
  перед общим normal нужны CU Cleanup, выход Guest и выгрузка профиля.
  Совместный цикл Applied ещё не выполнен. Контроллер и миграция рабочего сервера
  не расширяются.

## Нативные результаты

### Русская MUI: CP437 и CP866

В одной настоящей GUI CMD `/d` последовательно запущены два новых Windows
PowerShell NoProfile. Нативные API подтвердили фактические CP437 и CP866,
общего родителя и разные дочерние PID; оба reader завершились успешно.
Естественные UI-культуры PowerShell/Host/CLR остались en-US в обоих случаях.
Пользовательский список языков сохранился `ru, en-US`. В этой паре смена кодовой
страницы не объяснила fallback. Это отрицательный результат, а не русская
совместимость: Prepare Check не вызывался, новые языковые setters не применялись.
Артефакты независимо проверены; копия15990 штатно выключена, эталон сохранён.

Первая попытка ввода CMD была остановлена проверкой аргументов до MUI API:
диагностический QMP helper пропустил символ `/`. Она не входит в пару результатов.
Исправленный явный ввод `/d` подтверждён перед двумя действительными запусками.

### Сохранность стенда и сетевой контроль

Вчерашняя браузерная VM15989 штатно выключена после выхода обычного пользователя,
без Force. Перед выключением свежие native-чтения подтвердили CA0, исходные
WinINET flags9 с пустыми proxy/PAC/bypass, own GPO0 и18 NotConfigured, отсутствие
работающих собственных задач и прежние хеши двух учебных файлов.

Готовый Squid запущен с прежними образом, конфигурацией, CA и приватным state,
без изменения системного доверия. Однократные Linux-контроли дали PL302,
Moodle303 и собственный foreign Host403, client TLS verify0. Это проверка
готовности прокси перед новым Guest-циклом, не приёмка Windows-сети.

### Локальный normal при изменении учёток

До нового USB/network Apply обнаружено отсутствие объявленного SID учётки
`defaultuser0`. Причина исчезновения не установлена. Прежний модуль требовал
наличия каждого объявленного SID и отказал бы до снятия собственных ограничений.
Конфигурация не подменялась, исчезнувшая учётка не создавалась заново.

В модуле исправлена только обработка изменившегося списка для normal:
отсутствующие SID, переименования и новые SID сообщаются раздельно. Ошибка чтения
учёток, нарушения кода/config/ACL и конфликты политик по-прежнему дают отказ;
check/prepare остаются строгими. Изменение и 34 переносимые проверки независимо
приняты; эти проверки не считаются испытаниями Windows.

Штатный установщик доставил модуль без изменения конфигурации и metadata.
В 05:18:59 UTC исходная SYSTEM normal-задача запущена из локального GUI.
Свежий результат независимо проверен в 05:21:30: задача завершилась с кодом0,
`SourceCleanupCompleted=true`, `IdentityUnconfirmed=true`, `MissingAccounts`
содержит отсутствующий SID, `EffectiveMode=Unconfirmed`, `FullReady=false`.
Собственные USB/network уже были сняты; результат подтвердил доступность normal
при изменении учёток, но не снятие совместного Applied-набора. Конфигурация,
mode/usb metadata и прежние хеши двух учебных файлов сохранились.
Прокси работал: это ещё не завершение экзамена без сервера.

Общее число PersistentStore правил за время подготовки стенда выросло.
Причина не установлена; их удаление или восстановление старого набора
не выполнялись. Равенство всего PersistentStore этим результатом не заявляется.

### Shared PC RestrictLocalStorage: включение кандидата

На свежей копии эталона обычная учётка до подготовки прочитала два доступных
контрольных файла вне своего профиля через Explorer, IDEA, .NET и Java.
Собственная рабочая папка, компиляция и запуск Java работали.

Все семь исходных CSP-полей были null. Перед включением Shared PC заданы
`EnableAccountManager=true`, `AccountModel=2`, `DeletionPolicy=0`,
`SetEduPolicies=false`, `SetPowerPolicies=false`, `RestrictLocalStorage=true`;
их чтение подтверждено до `EnableSharedPCMode=true`. Затем независимо приняты
все семь целевых значений, три exemptions обычных учёток, системные WinRT
`IsEnabled=true`/`ShouldAvoidLocalStorage=true`, сохранность учёток и контрольных
файлов. Prepare выполнен один раз. После штатной перезагрузки WinRT-признаки
и проверенные файлы сохранились; семь raw CSP-полей после перезагрузки заново
не считывались.

Первичный сборщик результата ошибочно счёл журнал устаревшим из-за сравнения
локального DateTime с UTC. Отдельное чтение подтвердило успешную задачу и свежий
результат; исправлено только приведение времени сборщика к UTC. Часы Windows
и политики повторно не менялись.

После перезагрузки через штатную плитку вошёл настоящий новый Guest SID1003.
Его сеанс подтвердил `IsEnabled=true`/`ShouldAvoidLocalStorage=true`.

| Проверка при RLS=true | Наблюдение |
| --- | --- |
| Explorer «Этот компьютер» | C: и обычные домашние точки навигации скрыты; видны Downloads, floppy и CD. |
| Explorer, точные пути двух внешних файлов | Оба файла открылись в Notepad с исходным содержимым. |
| .NET и Java, те же внешние файлы | Оба файла прочитаны: 53 байта, исходный SHA256. |
| Собственная папка Guest под AppData | Запись, чтение, компиляция и запуск Java работают. |
| IDEA Welcome → Open File or Project | Chooser с кнопкой Select Folder показал одинаковое предупреждение «You can't save…» для обоих внешних каталогов и собственного файла в AppData. Файл через этот маршрут не открыт; это не отказ файлового API IDEA. |

RLS подтвердился как ограничение навигации и chooser. Он не запретил точный путь
через Explorer или прямое чтение API и помешал выбранному собственному workspace
в диалоге IDEA. Недоступность всех домашних папок или Downloads не проверялась
и не заявляется. Кандидат в таком виде не принят как общее решение. Промежуточная
проба обычной учётки при RLS=true не расширялась после отказа своего chooser.

После штатного выхода Guest его SID, профиль, ProfileList/HKU, каталог и запись
в родительском каталоге отсутствовали. Clear выполнен один раз: изменился только
`RestrictLocalStorage=true→false`, Shared PC остался включённым, три exemptions сохранены.
Это проверенное снятие настройки в опыте, а не обещание поддерживаемого
переключения RLS туда и обратно: CSP требует задать её до EnableSharedPCMode.

В обычном входе SID1001 вернулись Quick Access, C: и домашние папки. IDEA открыла
сохранённый собственный файл; рабочая папка, JDK, компиляция и запуск Java работают,
оба внешних файла вновь прочитаны .NET/Java. Независимое чтение в 05:49:03 UTC
подтвердило сохранность исходных файлов, настроек и отсутствие прежнего Guest.
Семь текущих raw CSP-значений взяты из защищённого SYSTEM Clear-результата,
а не из нового SYSTEM-чтения рецензента.

Следующая отдельная проба — `NoViewOnDrive`, DWORD4 для C: в Non-Administrators
MLGPO, без RLS и NoDrives одновременно. Используются LGPO и адресный PFE remove;
собственные home/workspace и обычная работа после снятия проверяются отдельно.
Это проба известного диска C:, не готовая политика всех томов и не запрет API.

Добавлена небольшая `tests/NetworkProbe.java` для прямого TCP без JVM proxy.
Компиляция для Java25 прошла на host JDK27; сетевой цикл с окончательным
исходником на Windows продолжается. Ошибка соединения сама по себе
не называется доказательством firewall.
