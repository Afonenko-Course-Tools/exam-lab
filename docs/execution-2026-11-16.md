## Уточнение задачи и архитектурная ревизия

Владелец уточнил: файловое ограничение должно быть широким и простым,
строгость может быть умеренной; нужно проверять близкие варианты. Поэтому
следующий шаг — штатный Shared PC `RestrictLocalStorage`, отдельно от отладки
Sandboxie и массовой переметки файлов. Списки исключений отдельных программ,
новые launchers и собственный механизм изоляции не добавляются.

Microsoft описывает `RestrictLocalStorage` как ограничение просмотра и сохранения
локальных данных через File Explorer. Свойство
[`ShouldAvoidLocalStorage`](https://learn.microsoft.com/en-us/uwp/api/windows.system.profile.sharedmodesettings.shouldavoidlocalstorage)
сообщает приложениям о необходимости скрыть точки доступа; Downloads, removable
и mapped drives описаны как исключения. Это описание интерфейса, а не доказанный
запрет Java API. Для canary планируется сравнить Explorer, IDEA File Open и Java
на известных контрольных файлах, сохранить работу JDK и собственного workspace,
затем проверить обычную учётку после снятия ограничения. По
[CSP SharedPC](https://learn.microsoft.com/en-us/windows/client-management/mdm/sharedpc-csp#restrictlocalstorage)
политика задаётся до включения Shared PC, поэтому используется свежая копия эталона.

Соседний простой вариант — пользовательская `NoViewOnDrive`: Microsoft явно
[не обещает запрета другим программам](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-windowsexplorer#noviewondrive).
Его следует оценивать как ограничение интерфейса, включая возможную помеху своему
workspace. MIC Low без объектного NR уже позволил чтение; массовая установка NR
не выбрана. Sandboxie сохраняется как отдельный кандидат после двух отрицательных
проб; продолжение COM-диагностики не является первым шагом по новому приоритету.

Независимая ревизия после первого RLS-цикла уточнила порядок: если NoViewOnDrive
мешает собственному учебному пути, после его адресного снятия и проверки обычной
учётки проверить отдельно более мягкий `NoDrives`. Microsoft описывает его как
[скрытие дисков без запрета доступа программ](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-windowsexplorer#nodrives).
Умеренная строгость допускает рассмотрение такого варианта, но не меняет смысла
результатов API. RLS также не исключён окончательно: собственный проект в штатном
Downloads ещё не проверен; предупреждение chooser для AppData не отвечает на этот
вопрос. Одно соглашение о рабочем каталоге не требует списка исключений, однако
RLS остаётся настройкой подготовки Shared PC, а не подтверждённым переключателем.

Ревизия поставки не обнаружила переноса частных QMP/MUI/Sandboxie-сборщиков в
установщик. После совместного нативного цикла приоритеты упрощения следующие:

- Проверить offline normal; повторные runtime-проверки Authenticode LGPO оценить
  по этому результату. Возможный отказ подписи без сети пока не установлен.
- Выбрать один файловый механизм и использовать имеющиеся LGPO/PFE, без нового
  launcher, изолятора профилей или пользовательских списков программ.
- После приёмки убрать стендовую QEMU/TestVM-привязку из существующего
  Install-LocalPilot, сохранив проверки возможностей и прав Windows.
- При следующей затронутой правке сократить дублирование schema/guards, сохранив
  повторную проверку после lock и самостоятельные проверки входов компонентов.

Владельцы единой конфигурации не меняются: назначения серверного прокси остаются
в Deployment, параметры конкретного Windows ПК — в его `pc.json`.

### Следующая небольшая проба по уточнению владельца

Владелец предложил закрыть другие диски и оставить на C: системные каталоги.
Для учебного пути также нужен собственный чистый профиль/workspace. Архитектурная
ревизия допускает эти крупные категории без списков отдельных приложений.
Ближайшая проба сочетает `NoViewOnDrive` для всех букв кроме C: и запрет только
просмотра списка корня C: и `C:\Users` для конкретного тестового Guest. Два ACE
не наследуются, массовое изменение ACL и восстановление снимка дескриптора
не используются. Это пока частный эксперимент, а не готовая доставка новым Guest.

Известный полный путь к доступному файлу остаётся обязательным контрольным обходом:
[Bypass traverse checking](https://learn.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/bypass-traverse-checking)
не позволяет считать запрет списка родителя запретом чтения дочерних файлов.
NoView также ограничивает Shell, а не Java API; реальный отказ съёмным носителям
обеспечивает отдельная уже испытанная USB-политика. Совместимость собственного
home/IDEA и обычный режим после снятия этих двух ACE ещё предстоит проверить.

Добавлена небольшая `tests/NetworkProbe.java` для прямого TCP без JVM proxy.
Компиляция для Java25 прошла на host JDK27; окончательный исходник также выполнен
на Windows в следующем совместном цикле. Ошибка соединения сама по себе
не называется доказательством firewall.
