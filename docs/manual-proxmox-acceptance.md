# Ручная приёмка ExamLab с Proxmox

Текущий прогон проводится на локальной Windows VM с тестовыми данными
и экзаменационным сервером на Proxmox VM 103. При последующей приёмке
на выделенном Windows-ПК с физической флешкой потребуется отдельная
регистрация. Для университетской Moodle нужен отдельный прогон
с выданной владельцем тестовой записью.

## Подготовка Proxmox

1. Возобновите [выделенную VM 103](proxmox-exam-pilot.md) с адресом
   `10.135.250.231`, прежними данными, ключами и CA. Сверьте защищённую панель,
   контроллер, Wazuh и учебный маршрут Moodle → LTI → PrairieLearn через Squid.
   Проверьте выдачу заготовки назначенной работы с исправлением кириллических
   аргументов на Windows. [Последний протокол VM](execution-2026-11-20.md) ·
   [Настройка Deployment](https://github.com/Afonenko-Course-Tools/prairielearn-deployment/blob/72f965b231b1526ff47544789f16a521b6bdf03a/deploy/fixture-server.md)
2. Подготовьте на VM 103 административный каталог `tools_dir`.
   [Список инструментов](../vm/proxmox/windows-release-tools.tsv) фиксирует
   имена, версии и официальные источники. Если готовые файлы уже переданы
   по административному каналу, используйте этот каталог. Для первого
   наполнения из указанных источников выполните на VM следующую командную группу.

   ```bash
   (
     set -e
     mkdir -p "$tools_dir"
     while IFS=$'\t' read -r name version url; do
       [[ $url == https://* ]] || continue
       curl --fail --show-error --location --proto '=https' --proto-redir '=https' \
         --output "$tools_dir/$name.part" "$url"
       mv -- "$tools_dir/$name.part" "$tools_dir/$name"
     done < vm/proxmox/windows-release-tools.tsv
   )
   ```

   Сгенерируйте кэш зависимостей по ZIP назначенной пилотной работы с Gradle 9.8.2.
   [Сценарий наполнения кэша](../scripts/vm/build-pilot-gradle-cache.sh)
   собирает зависимости основного и тестового classpath этой работы.

   ```bash
   bash scripts/vm/build-pilot-gradle-cache.sh "$gradle" "$starter_zip" \
     "$tools_dir/gradle-exam-cache.zip"
   ```

3. Из проверенной Git-ревизии соберите комплект и отдельный CMD.
   `controller_ca_der` и `squid_ca_der` — публичные сертификаты CA пилота в DER,
   полученные по административному SSH с проверенным ключом хоста.
   Сертификат HTTPS контроллера на VM 103 должен содержать IP SAN
   `10.135.250.231` и DNS SAN `controller.exam-server-20261119.test`.
   CMD проверяет DNS-имя и подставляет адрес через `curl --resolve`, поэтому
   добавлять запись в DNS или менять файл `hosts` Windows не требуется.
   Для сборки используйте тот же набор файлов из `tools_dir`, который будет
   опубликован. Сохраните отпечатки CMD, ZIP и PowerShell из вывода сборки
   вместе с версией.

   ```bash
   release_dir=$(mktemp -d)
   launcher_dir=$(mktemp -d)
   python3 scripts/build-windows-release.py --output "$release_dir" \
     --launcher "$launcher_dir/Start-ExamLab.cmd" --tools-dir "$tools_dir" \
     --controller-ca "$controller_ca_der" --squid-ca "$squid_ca_der" \
     --moodle-activity-url 'https://moodle.exam-server-20261119.test:21643/mod/lti/view.php?id=2'
   ```

   Опубликуйте комплект из той же ревизии на VM. Сценарий сверяет SHA-256 ZIP
   и исходных файлов инструментов с установщиком. Инструменты доступны в
   `/install/exam-lab-<ревизия>/tools/`; комплект и сценарий — в
   `/install/exam-lab-<ревизия>.zip` и `/install/exam-lab-<ревизия>.ps1`.
   Повтор публикации сверяет содержимое существующих файлов.

   ```bash
   sudo bash vm/proxmox/publish-windows-release.sh "$release_dir" "$tools_dir"
   ```

4. Подключите [маршруты загрузки](../vm/proxmox/exam-lab-install.nginx.conf.example)
   внутри действующего блока HTTPS `server` для `10.135.250.231:21650`.
   На настроенной VM конфигурация находится в
   `$HOME/exam-lab-campaign/state/controller-tls/nginx.conf`.
   Поместите копию фрагмента рядом с конфигурацией под именем
   `exam-lab-install.nginx.conf` и добавьте в блок строку
   `include exam-lab-install.nginx.conf;`. Выполните проверку и перечитайте
   конфигурацию от имени администратора, запустившего этот Nginx.

   ```bash
   tls_dir="$HOME/exam-lab-campaign/state/controller-tls"
   nginx -e stderr -p "$tls_dir/" -c nginx.conf -t
   nginx -e stderr -p "$tls_dir/" -c nginx.conf -s reload
   ```

   Из испытательного сегмента проверьте HTTPS с CA контроллера и точным IP
   сервера. Получите PowerShell, ZIP выпуска и все инструменты из
   каталога текущей ревизии. Проверьте ответ 404 для неизвестного пути в
   `/install/` и прежнюю авторизацию панели преподавателя.
   Маршрут контроллера и порты учебных служб задаёт действующая конфигурация.

5. Опубликуйте CMD через `vm/proxmox/publish-http-bootstrap.sh` для адресов
   пилотных Windows-клиентов. Передайте SHA-256 и ссылку на HTTP-загрузку по
   административному SSH с закреплённым ключом хоста. Для отправки отчётов
   создайте `/var/lib/exam-lab-controller/diagnostics` с владельцем
   `examcontroller` и режимом `0700`. Подключите HTTPS-фрагмент
   `exam-lab-diagnostics.nginx.conf.example` с точными CIDR пилота.

6. Подключите [фрагмент регистрации](../vm/proxmox/exam-lab-enrollment.nginx.conf.example)
   к HTTPS-серверу. Используйте фактический адрес изолированного клиента `/32`
   и имеющийся закрытый секрет прокси контроллера. Храните фрагмент с правами
   `0600`. Окно допускает первый запрос с этого адреса. Открывайте его по одному
   ПК после подтверждения выделенности источника. Общий NAT нескольких
   доступных отправителей для такого допуска не подходит.
7. Создайте новый ПК контроллера с исходным `normal` и выделенного агента Wazuh.
   Подготовьте закрытый `0600` файл с объектом `network`, объектом
   `registration` (`url`, `deviceId`, `token`) и строкой `wazuhKey` с извлечённым
   ключом Wazuh в Base64. В `network` укажите параметры испытательного сегмента.
   Для VM 103 это Squid `10.135.250.231:21680`, `ControllerEndpoint`
   `10.135.250.231:21650`, `WazuhEndpoint` `10.135.250.231:1514`, DHCP-сервер
   при его использовании и список `TechnicalAccess`. URL регистрации равен
   `https://10.135.250.231:21650/exam/v1/poll`. Windows сама читает обычные SID.
   До передачи ссылки оператору откройте окно в отдельном сеансе сервера.

   ```bash
   sudo -n -u examcontroller python3 -Es /opt/exam-lab/controller/current/server.py \
     --db /var/lib/exam-lab-controller/controller.sqlite3 \
     arm-enrollment --receipt "$server_receipt" --minutes 20
   ```

   После первого итогового отчёта закройте окно и удалите исходный временный
   файл на сервере. Повторный запуск CMD использует защищённую запись на ПК.

   ```bash
   sudo -n -u examcontroller python3 -Es /opt/exam-lab/controller/current/server.py \
     --db /var/lib/exam-lab-controller/controller.sqlite3 close-enrollment
   ```

   [Регистрация ПК](windows-controller.md) · [Сетевые параметры](windows-network-component.md) ·
   [Регистрация Wazuh](windows-wazuh-pilot.md)

## Подключение TUI на VM 103

Подготовьте публичный ключ SSH владельца и код контроллера из той же полной
Git-ревизии, что и Windows-комплект. На VM 103 выполните от имени администратора
с проверенным ключом хоста. Замените переменные путями передачи и согласованным
идентификатором экзамена. Приватный ключ остаётся у владельца.

```bash
sudo -n bash vm/proxmox/configure-owner-tui.sh \
  "$controller_source" "$revision" "$exam_id" "$owner_public_key" "$file_trace_exam"
sudo -n bash vm/proxmox/activate-controller-tui.sh "$revision"
```

Активация останавливает только контроллер, переносит согласованную копию его
SQLite в закрытый каталог `/var/lib/exam-lab-controller` и проверяет рабочий HTTP
вход и Unix-сокет. При сбое она возвращает прежнюю службу с исходной базой.
Рабочий контроллер запускается как `examcontroller`; HTTPS-вход контроллера,
Wazuh, Moodle и PrairieLearn продолжают использовать свои прежние адреса.
Для административной диагностики используется [обёртка контроллера](../scripts/vm/exam-on-server.sh).

До передачи владельцу те же команды позволяют проверить следующую ревизию
с действующей SQLite. При ошибке запуска активация возвращает прежнюю
systemd-службу. Команда запуска панели каждый раз выбирает активную ревизию.

Владелец импортирует [профиль Muon](../vm/proxmox/exam-lab-owner.muon.ssh-config.example)
с собственным приватным ключом, сверяет ключ хоста и подключается как `examowner-ssh`.
В терминале сервера он запускает `exam-lab-tui`. Служебная учётная запись
`examowner` сохраняется для авторизации панели и журнала действий владельца.
[Настройка Muon](../controller/README.md)

Проверьте вход владельца, получение списка ПК и отказ снятия тревоги из
другой учётной записи. `Q` возвращает владельца в оболочку. Обычная учётная
запись оператора получает доступ к SQLite только
через административное обслуживание с повышением.

## Установка на Windows

Для полной установки нужна автономная Windows x64, сборка `19041` или
новее, с поддержкой Shared PC. Клиенту нужен маршрут к VM 103 из
`10.0.0.0/8` и попадание в разрешённую сеть HTTP-загрузки.
Скачайте CMD в Edge, сверьте выданный SHA-256 и подтвердите UAC по
[сквозной инструкции](pwsh7-pilot-acceptance.md#установка-и-повтор).
CMD добавляет закреплённый корневой сертификат и при необходимости
устанавливает PowerShell 7.6.10 x64. Комплект и инструменты загружаются
с `10.135.250.231:21650` с проверкой TLS и SHA-256.

Установка запускает подготовку Shared PC и ждёт свежего успешного отчёта задачи.
На рабочем столе появляется ярлык `ExamLab - Moodle`, который открывает LTI
через Squid с отдельным профилем Edge текущего пользователя. Регистрация
выполняется автоматически после проверки HTTPS.
Если установщик запросил перезапуск, перезапустите Windows, заново сверьте
SHA-256 CMD и запустите тот же файл. После итогового успешного отчёта
назначьте экзамен и проверьте опрос контроллера до входа в Windows.

## Маршрут приёмки

На каждом ПК запишите выпуск клиента, версию и редакцию Windows,
идентификатор назначения, время обоих допусков и серверный ID попытки.
Используйте синтетические файлы и ответы. Серверное назначение, сводку и
подтверждение текущего Guest выполняйте по
[действиям панели](../controller/README.md#терминальная-панель-преподавателя).
ПК автоматически включает Wazuh для экзамена. После машинного допуска сверяйте
состояние `Active` на менеджере и повторите проверку на новом экзамене после
`normal`. Для проверки чтения используйте отдельное административное
подключение, которое работает при активном фильтре и открытом Guest. Например,
для уже подготовленного WinRM укажите адрес административного источника и
порт слушателя в `TechnicalAccess`, а затем проверьте доступ до входа Guest.
Привяжите контроль к текущему сеансу.
[Агент Wazuh](windows-wazuh-pilot.md) · [Проба чтения](windows-alert-file-audit.md)

Для учебного входа в каждом новом Guest воспользуйтесь ярлыком `ExamLab - Moodle`.
Преподаватель сначала сверяет готовность текущего места, затем даёт команду
начать. При диагностике Edge можно открыть явно.
[Параметры Edge](https://learn.microsoft.com/en-us/deployedge/edge-learnmore-cmdline-options-proxy-settings)

```powershell
$edgeData = Join-Path $env:LOCALAPPDATA 'ExamLabEdge'
$moodle = 'https://moodle.exam-server-20261119.test:21643/'
Start-Process msedge.exe -ArgumentList "--user-data-dir=`"$edgeData`" --proxy-server=http://10.135.250.231:21680 $moodle"
```

| Этап | Что проверить |
| --- | --- |
| Обычная работа до экзамена | Откройте прежний IDEA-проект и проверьте Run, Debug и Git. Убедитесь, что обычный файл читается и записывается, флешка читается, а контрольный сетевой адрес доступен. Завершите проверку установки повтором. |
| Машинный допуск | Проверьте состав обычных SID. Запустите локальное задание `ExamLab-Local-prepare` и проверьте его результат. Выключите клиент, выдайте новое назначение и включите его. Проверьте появление «Можно входить» до интерактивного входа. |
| Допуск Guest | Войдите через плитку Guest. Проверьте запись и повторное открытие своего проекта, отказ чтения USB до и после переподключения, отказ чтения контрольных файлов, доступность прокси и блокировку прямой сети. Свяжите подтверждение преподавателя с текущим Guest и дождитесь «Можно начинать». |
| Учебная работа | Выполните Moodle → LTI → назначенная работа PrairieLearn. Проверьте отказ для постороннего пути Moodle и другой работы PrairieLearn. Скачайте ZIP, откройте в IDEA, выполните сборку, тесты, Run и Debug. Сохраните изменения, закройте и снова откройте проект и сдайте ответ. |
| Сеть и сдача | В отдельной попытке прервите связь до подтверждения сдачи. Сохраните незавершённый ответ и оставьте сеанс открытым. Восстановите связь, получите ответ PrairieLearn и сверьте попытку, результат и принадлежность. |
| Wazuh | Проверьте, что обычный учебный маршрут не вызывает тревогу. Проведите контрольное чтение с настроенным аудитом. Сверьте одну тревогу с её ПК, событием и текущим Guest. Снимите актуальную тревогу из TUI владельца и дождитесь подтверждения этого же Guest. |
| Автономное завершение | Выйдите из Guest после подтверждённой сдачи. При недоступном для клиента сервере запустите `ExamLab-Local-normal` из повышенного обычного входа. Проверьте результат задания, прежний проект, USB, Java/Git и обычную сеть. |
| Следующий сеанс | Восстановите связь. Проверьте, что прежнее назначение не вернуло ограничения. Задайте новый ID экзамена и убедитесь, что следующий Guest чистый и требует нового подтверждения. |

Маршрут с фактическим отказом фиксируется как `FAIL`, пропущенная проба
как `NOT_TESTED`. В предыдущем прогоне штатный Shared PC отклонил запрос UAC
из Guest, поэтому локальное подтверждение тревоги осталось `FAIL`. Также
остаются проверка полного файлового покрытия и устойчивость допуска при
одновременной работе IDEA и Gradle. Для этого комплекта `FullReady=false`. После успешного
прогона на VM повторите таблицу на отдельном Windows-ПК с физической флешкой.
