# Стендовый аудит AppLocker для Guest

Сценарий предназначен для отдельной Windows VM QEMU с установленным ExamLab.
Он добавляет два правила коллекции `Exe` в режиме `AuditOnly`. `Allow *`
сохраняет запуск приложений. `Deny` относится к точному SID действующего Guest
и одному синтетическому EXE в защищённом каталоге `Program Files`. Аудит
позволяет наблюдать предупреждение `8003` при успешном запуске этого образа.
Предыдущая нативная проверка `8003` проведена под обычным токеном Medium.

## Запуск аудита

Оператор заранее готовит независимый местный административный доступ на VM.
Сверяет хеш сценария и вручную помещает его в установленный защищённый каталог
`Program Files\ExamLabAlert\Private`. Штатный комплект RC20 этот сценарий
не устанавливает. Запуск из доверенного задания SYSTEM использует
64-битный Windows PowerShell 5.1 и сверенное имя компьютера. Штатный ExamLab
должен видеть активное назначение `exam` и текущий Guest. Сценарий проверяет
тот же SID, номер сеанса, загрузку и ревизию назначения непосредственно перед
записью. Кандидат допускает пустые Local и Effective, отсутствие внешнего
присоединения и AppLocker CSP, а также исходный `Running/Manual` у AppIDSvc.
Состояние службы подготавливают отдельным штатным шагом. Чтение
Local и Effective охватывает Group Policy. CSP проверяется отдельно через
WMI Bridge. [Документация Microsoft об AppLocker CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/applocker-csp)

Оператор отдельно создаёт новый синтетический образ. Используйте защищённые
штатные права `Program Files`. Сверьте чтение и запуск под Guest и отсутствие
у него записи, смены ACL и удаления. Сценарий независимо проверяет владельца,
права обоих объектов и SHA-256 копии перед применением.

```powershell
$fixture = Join-Path $env:ProgramFiles 'ExamLab-AppLockerCanary'
if (Test-Path -LiteralPath $fixture) { throw 'Путь уже занят' }
[void][IO.Directory]::CreateDirectory($fixture)
$canary = Join-Path $fixture 'AppLockerCanary.exe'
[IO.File]::Copy((Join-Path ([Environment]::SystemDirectory) 'cmd.exe'), $canary, $false)
```

Этот файл принадлежит оператору на срок пробы. После проверки снимите
политику, сохраните свидетельства и уберите контрольный файл отдельным
адресным действием.

В подтверждённом сеансе SYSTEM выполните команду с фактическим именем VM.

```powershell
$name = 'EXAM-LAB-VM'
$script = Join-Path $env:ProgramFiles 'ExamLabAlert\Private\Invoke-ExamLabAppLockerPilot.ps1'
& $script -Action Audit -ExpectedComputerName $name -EnableVmAudit
```

Защищённое намерение записывается до вызова `Set-AppLockerPolicy`. Оно
фиксирует идентификаторы правил, Guest, SHA-256 контрольного образа и границу
журнала. Файл фазы отдельно отмечает начало записи и подтверждение полного
совпадения Local и Effective. После одного вызова записи сценарий ждёт
совпадения до 12 секунд. Новый `Audit` при незакрытой пробе останавливается.

```powershell
& $script -Action Status -ExpectedComputerName $name
```

Перед запуском контрольного EXE дождитесь `Loaded=true`. Для этого нужны
совпадающие Local и Effective, работающая AppIDSvc, тот же действующий Guest,
новая запись `8001` и последующая `8002` с GUID собственного `Allow`.
При задержке повторяйте чтение. В предыдущей нативной пробе запись о загрузке
появилась примерно через две минуты после раннего контрольного запуска.
У браузера, IDEA, Gradle и Java нужны свои нативные действия и свидетельства.
[Смысл событий AppLocker](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/using-event-viewer-with-applocker)

Из проверяемого Guest запустите `AppLockerCanary.exe` из каталога
`Program Files\ExamLab-AppLockerCanary` с аргументами
`/d /c echo EXAMLAB_APPLOCKER_CANARY`. Сопоставьте код 0 и маркер с записью
`8003` для точного пути, SID и GUID `Deny`. Для контроля штатного запуска
используйте прежний `System32\cmd.exe`. Сырые журналы и намерение храните
в закрытой области стенда.

## Автономное снятие

После выхода Guest из местного административного канала запустите этот же
сценарий от SYSTEM. Для снятия достаточно локальной Windows и сохранённого
намерения. Команда доступна при недоступном контроллере.

```powershell
& $script -Action Normal -ExpectedComputerName $name
```

Перед снятием сценарий полностью сверяет собственные правила, обе политики
и отсутствие сторонних источников. Пустая политика задаётся заново явным
XML. Этот вызов допустим только при полном совпадении собственных правил.
При расхождении сценарий возвращает ошибку, а неизвестные правила требуют
отдельного административного разбора. Сценарий проверяет Local и Effective
после одного вызова записи. `Normal` выводит наблюдаемое состояние AppIDSvc.
У службы отдельный жизненный цикл. При прерывании после начала записи одно
пустое чтение не определяет исход. Команда сохраняет намерение, а `Status`
показывает фазу и совпадение обеих политик. Повторный `Normal` после успешного
снятия сообщает, что собственного намерения больше нет.

`LocalEmpty` и `EffectiveEmpty` подтверждают чтение источников Group Policy.
`RuntimeClearConfirmed=false` указывает, что состояние кэша EXE в `appid.sys`
требует отдельной нативной пробы. На VM 104 после пустых Local и Effective
и следующей загрузки Windows события EXE всё ещё содержали GUID предыдущего
правила. Сверяйте свежий запуск обычного приложения с журналом AppLocker.
Одна запись `8001` или пустой XML сами по себе не подтверждают смену
правил, которыми фактически пользуется Windows.
[Применение политик и кэш appid.sys](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/applocker/applocker-processes-and-interactions)

Этот вызов снимает локальные настройки стендового AppLocker. Штатная локальная задача ExamLab
`normal` отдельно возвращает USB, сеть и Wazuh. Практическое возвращение
рабочего места проверяется повторным входом и запуском обычного проекта.
`FullReady` сохраняет значение действующего договора. В прежней нативной пробе
проверялись три коллекции, включая Appx. Одноколлекционный вариант этого
сценария требует отдельной нативной приёмки. Принудительный AppLocker, правила
сценариев и широкий учебный прогон Guest имеют отдельные критерии.
