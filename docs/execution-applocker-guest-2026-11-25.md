## Границы проверки

- Для AppLocker используется отдельный административный сценарий стенда. Он ограничен одним подтверждённым Windows Guest, учитывает полный состав локальной и действующей политики и снимает собственное изменение. Для пробы `Enabled` требуются принятый учебный маршрут в `AuditOnly` и проверка восстановления. Основной переключатель ExamLab сохраняет `FullReady=false`.
- Учебный маршрут использует подписанный запуск Moodle, штатный Native ZIP и сдачу в PrairieLearn. В этой фазе сохраняются действующие конфигурации курса, Gateway и учебного сервера. Сохранённые Linux-проверки кандидата привязки имени к Guest относятся к отдельному договору. [Договор привязки](exam-guest-lti-binding.md)
- Единственный основной Check — RC20 из `2f9865ed3bb0ab2c031ff082d5ff765c9826fdee`. SHA-256 CMD `bb1731c1e78724503afb5a20ef95eb709d68145bd4c66e747e57b423c9fc4148`. [Открыть Check RC20](http://10.135.250.231/c)

## Профиль записи

WPR запущен в файловом режиме с профилями `FileIO.light`, `Network.light` и `Registry.light`. В начальном замере у System Collector и Event Collector было по 60 буферов по 1024 КиБ. Системный набор включает файловые операции, процессы и потоки, загрузку образов, реестр, диск, CPU и память. Для сети доступны провайдеры TCP/IP, Networking-Correlation, NCSI и WinQuic. Счётчики потерь относятся к соответствующим коллекторам, а покрытие стадий и сопоставление операций проверяются отдельно.

С тома `T:` после остановки, в режиме только чтения без восстановления NTFS, обнаружены фрагменты Event Collector (12 394 168 320 байт) и System Collector (12 357 468 160 байт). Суммарно 24 751 636 480 байт. Последняя запись файлов — 11:14:24, примерно через 58 минут после запуска. Средняя скорость двух файлов составила около 7,1 МБ/с. В 11:22:52 полная закрытая копия каталога подтверждена `cmp` и SHA-256, время изменения сохранено. Режим файлов ETL — `0600`. Также сохранены системный журнал, журналы AppLocker и планировщика из режима только чтения.

В заголовках обоих ETL есть время завершения 11:14:24, а записанные 11 820 и 11 785 буферов по 1 МиБ совпадают с длиной файлов. Для обоих коллекторов `EventsLost=0` и `BuffersLost=0` по заголовкам. Это счётчики сохранённых фрагментов. Объединённый ETL не создан, полнота событий отдельных операций и количество несопоставленных операций широкого окна не установлены. По измерениям прежних прогонов полный XML занял бы ориентировочно 311–386 ГБ. Его не создавали. [Закрытая сводка заголовков и ресурсов](../.local/trace-expanded-20261125/guest-wide/integrity-and-resources.json)

После восстановления нативный `wpr.exe` вернул `0xc5600602 Invalid option: -merge` на диагностический вызов без путей к файлам. Принятый экспорт — две раздельные копии исходных ETL и их манифест. [Закрытый манифест экспорта](../.local/pve-expanded-20261124/25-second-wide-preserved.txt)

Тесты контроллера открывают loopback-сокеты и выполнены с разрешением на этот вызов. Эти проверки отделены от наблюдений Windows.

Отдельный кандидат AppLocker сохранён в `4c59a5b27d46b04eda8239fbeb092188d5c27e5c`, уточнение по результатам проверки — `521236830390095bb6a39cfe423d35d3ce07e80e`. SHA-256 сценария `4d48987498b0358984e0075d2d84064ce69ff00b76b3c2dc43249d5ba04399af`. Независимый рецензент проверил локальный административный запуск, защищённое намерение до первой записи, обработку неопределённого исхода, точное чтение обеих политик и адресное действие `Normal`. Сценарий проверяет готовность AppIDSvc, а `Normal` сообщает об очистке политик Group Policy. Состояние кэша драйвера требует подтверждения нативным событием. Тест сценария и проверка синтаксиса прошли в Linux. На VM используется временный помощник, ранее проверенный на обычном токене и уточнённый для текущего Guest.
