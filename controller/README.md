# Контроллер экзамена на локальном стенде

Преподаватель задаёт режим зарегистрированного ПК с Linux-стороны стенда.
Задача Windows от SYSTEM сама опрашивает контроллер и исполняет установленные
локально действия. Сервер отвечает только режимом и идентификаторами назначения.
Договор опроса не зависит от текущего IP компьютера. Moodle, Gateway и PrairieLearn
продолжают вести свои регистрации, личность студента, задания и сдачи.

## Запуск и регистрация

Достаточно Python 3.9+ со стандартным `sqlite3` и входа HTTPS в Deployment.
Nginx публикует только `POST /exam/v1/poll` и передаёт запрос на
`http://127.0.0.1:21651` без изменения пути, с прежним `Authorization`.
На этом пути отключите кэширование, ограничьте тело запроса 4 КиБ и направляйте
токен исключительно по HTTPS. Windows проверяет имя или IP сертификата и его
доверенную цепочку. Загрузка `server.py` обслуживает только IPv4 loopback.

В терминале Linux от лица выделенной учётной записи стенда выполните из корня
checkout команды регистрации. Выберите постоянный приватный каталог вне Git.

```sh
umask 077
state_dir=/var/lib/exam-lab-controller
db_path="$state_dir/controller.sqlite3"
(set -C; python3 controller/server.py --db "$db_path" register pc-01 > "$state_dir/pc-01.token")
python3 controller/server.py --db "$db_path" serve
```

Каталог предварительно создаётся с правами `0700` и владельцем этой учётной
записи. `register` записывает в стандартный вывод одноразовую копию нового
случайного токена и создаёт назначение `normal` с ревизией 1. Передайте ПК его
постоянный `deviceId` и токен в приватном административном комплекте. Храните
токен на Windows в файле, доступном SYSTEM и администраторам. Оставьте его вне
журналов, параметров командной строки, Git и общего комплекта установщиков.
Сервер хранит только SHA-256 токена. При утере выпустите новый через
`rotate-token pc-01`, сохраните его в защищённый файл и обновите комплект ПК.
Предыдущий токен сразу перестаёт действовать, задания и ревизия сохраняются.

## Назначение и наблюдение

Во втором терминале той же учётной записи задайте `db_path` с тем же путём и
укажите новый идентификатор для каждого запуска экзамена.

```sh
python3 controller/server.py --db "$db_path" assign pc-01 exam --exam-id java-2026-11-19-a
python3 controller/server.py --db "$db_path" status pc-01
python3 controller/server.py --db "$db_path" assign pc-01 normal
```

Команда с текущим назначением повторяется без смены его ревизии. После `normal`
или другого экзамена предыдущий идентификатор закрыт для этого ПК. Чтобы снова
начать экзамен после локального `normal`, преподаватель указывает новый ID.
Остановленный контроллер можно запустить повторно с тем же файлом БД. При
переносе сохраняются запись регистрации и все номера назначений этого ПК.

`status` отображает следующие значения.

| Поле | Значение |
| --- | --- |
| `assignment` | Последнее назначение преподавателя. |
| `latestReport` | Последний принятый отчёт ПК с результатом и локальным временем `observedUtc`. |
| `lastApplied` | Последний принятый `applied`, включая историческое подтверждение после `overridden`. Текущее состояние показывает `latestReport` с учётом ревизии и возраста связи. |
| `lastSeenUtc`, `connectionAgeSeconds` | Серверное время и возраст последнего допустимого опроса. |
| `connection` | `never` до первого опроса, `fresh` при возрасте меньше порога, `stale` при достижении порога. Порог `--stale-after` по умолчанию 45 секунд. |

`applied` означает подтверждение установленным переключателем. `source-applied`
означает результат записи источников политик, действие которых проверяют отдельно.
`blocked` означает отказ проверки допуска, `error` ошибку действия или проверки,
`overridden` локальное завершение назначения `exam`. Преподаватель подтверждает
готовность первого Guest проверками внутри фактического сеанса.

## Обмен с Windows

`POST /exam/v1/poll` принимает UTF-8 `application/json` и `Authorization: Bearer`.
Для первого запроса отправляется `{"deviceId":"pc-01","result":null}`. Дальше
`result` содержит поля следующего формата.

```json
{
  "deviceId": "pc-01",
  "result": {
    "revision": 2,
    "mode": "exam",
    "examId": "java-2026-11-19-a",
    "outcome": "blocked",
    "reason": "full-not-ready",
    "fullReady": false,
    "observedUtc": "2026-11-19T14:03:25.123Z"
  }
}
```

Успешный ответ содержит `deviceId`, `revision`, `mode` и `examId`. Режим
`normal` передаётся с `examId: null`. Оба идентификатора используют от 1 до 64
знаков `[A-Za-z0-9._-]` и сравниваются с учётом регистра. Ревизия целая, от 1
до 2147483647, возрастает при смене назначения. В `result` пара `mode` и `examId`
соответствует назначенной ревизии, в том числе при `overridden`. `reason` равен
`null` для `applied` и содержит от 1 до 64 знаков `[a-z0-9-]` для остальных
результатов. `observedUtc` передаётся в UTC с точностью до миллисекунд. В статус
сервер также записывает своё `receivedUtc` при приёме нового отчёта.
Для `applied` в режиме `exam` требуется `fullReady: true`. При `source-applied`,
`blocked`, `error` и `overridden` требуемое значение `fullReady` равно `false`.

Устройство вправе повторять отчёт и доставлять его позднее. Сервер проверяет
его соответствие когда-либо назначенному этому устройству кортежу. Более ранняя
ревизия сохраняет новый `latestReport`, а `overridden` сохраняет приоритет над
опоздавшим подтверждением той же ревизии. `lastSeenUtc` обновляется только при
корректном опросе. Ответы об ошибках содержат только `error`; Windows сохраняет
текущую конфигурацию. Запрет повторного применения старого `exam` после локального
`normal` и при перезапуске обеспечивается защищённым состоянием Windows.

Проверки сервера запускаются из корня репозитория командой
`python3 -B -m unittest discover -s controller`. Они создают временную БД и
проверяют HTTP на loopback. Доверие TLS, запуск Windows до входа, восстановление
и появление первого Guest проверяются отдельно на стенде.
