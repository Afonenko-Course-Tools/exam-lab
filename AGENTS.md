# Инструкции для работы над exam-lab

Начинайте с README, `docs/requirements.md` и `docs/work-plan.md`.
Последние прямые указания пользователя имеют приоритет. Сохраняйте существующие
рабочие деревья, незакоммиченные изменения и открытые PR.

Не расширяйте небольшой пилот до проверки Guest, USB, сетевых ограничений
и локального завершения. Используйте готовые средства Windows, PowerShell,
планировщик заданий и стандартные средства виртуализации. Собственные пакетные
менеджеры, форматы блокировки зависимостей, универсальные движки обновления,
очереди и протоколы доказательств не входят в задачу.

Переключатель экзамена применяет явные скриптовые настройки обычного и
экзаменационного режимов. Снимки состояния Windows и полный обратный импорт
firewall, GPO или реестра в этот механизм не входят. Он снимает только свои
ограничения; конфликт с чужой политикой выявляется до изменений. Shared PC
допускается подготовить однократно при доказанной сохранности обычных занятий.
Копии тестовой VM и резервирование учебных данных при миграции — отдельные задачи.

Для файлового ограничения по последнему уточнению владельца допустим только
open source или небольшая обвязка штатных механизмов. Рекурсивное добавление ACL
для нашего Guest теперь разрешено при сохранности обычных занятий; прежний запрет
массовой ACL-обработки в этой части отменён. Снимки/сброс DACL, смена владельца
и удаление чужих ACE этим не разрешены. 17 ноября владелец возобновил реализацию
и испытания до 22:00 Europe/Minsk; вчерашняя остановка снята. Сегодня ручные
проверки владельцем недоступны; они не считаются выполненными по VM-результатам.
Кандидаты и границы: `docs/file-isolation-options-2026-11-16.md`.

Привязывайте ограничения к экзаменационному пользователю, где это подтверждено
проверкой. Для общих изменений Windows проверяйте сохранность обычных занятий
и локальное восстановление без сервера. Не применяйте экспериментальные политики
к рабочему хосту или аудиторным ПК вместо одноразовой Windows VM.

У файла и контракта в одной фазе один владелец. Автор не принимает собственную
реализацию. Код, примеры и тесты пишет назначенный технический исполнитель.
Не выдавайте проверки с подменёнными API за испытания настоящей Windows.
Ограничение песочницы не считайте доказательством отсутствия инструмента на хосте.

Перед новой фазой, существенным изменением договора или накоплением обходных
решений проводите короткую архитектурную ревизию всей платформы. Рассматривайте
сквозной учебный путь, действующие договоры курсов, Platform, Deployment и
exam-lab, владельцев конфигурации и сохранность данных. Сначала выясняйте причину
отказа штатного механизма; проверяйте возможность упростить, удалить дублирование
или заменить временный обход готовым средством до добавления нового слоя.
Независимый рецензент оценивает эти границы и необходимость сложности наряду
с корректностью кода. Упрощение входит в завершение фазы; разовая диагностика
не становится частью поставки автоматически. Существенные решения и причины
отказа от подходов сохраняйте в документации Git; отдельный протокол допуска
для мелких изменений не нужен.

Новые README, документацию и описания PR пишите только по-русски по
[общему языковому правилу](https://github.com/Afonenko-Course-Tools/quarto-course/blob/main/docs/russian-language-policy.md).
