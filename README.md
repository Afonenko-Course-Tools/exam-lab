# Экзаменационная среда Windows

`exam-lab` предназначен для проведения экзаменов по Java на обычных аудиторных
Windows-ПК. Студент работает в чистом гостевом сеансе, не может читать подсказки
с флешки и имеет сетевой доступ только к согласованным PrairieLearn и Moodle.
Обычные занятия, учётные записи и файлы должны сохранять работоспособность
независимо от экзаменационного контроллера.

Идёт локальный пилот на отдельной QEMU/KVM VM. Windows 10 Enterprise Evaluation
22H2, сборка 19045.2006, установлена из официального ISO; технический доступ
через WinRM проверен. Приёмка экзаменационного режима ещё не завершена.
Устанавливать эти экспериментальные политики на аудиторные ПК пока нельзя.

Целевой механизм разделён на однократную подготовку и переключение
«экзамен / обычная работа». Shared PC можно оставить включённым при сохранности
обычных занятий. Переключатель снимает только собственные ограничения,
без снимков Windows и полного обратного импорта политик. Этот упрощённый
вариант ещё проходит реализацию и испытания.

## Начало работы

1. Прочитайте [согласованные требования](docs/requirements.md).
2. Для разработки следуйте [плану работ и автоматизации](docs/work-plan.md).
3. Перед переносом старого кода изучите [оценку поставки 0.1.0](docs/source-review.md).

Порядок исполнительной сессии описан в
[стартовом поручении](docs/start-prompt.md), фактические результаты — в
[отчёте локальной сессии](docs/execution-2026-11-15.md).

Первый проверяемый результат — небольшой Windows-пилот: запрет чтения USB
для настоящего Guest, сетевые правила и локальное завершение экзамена без сервера.
После проверки этого пути добавляются повторные испытания, затем управление из Proxmox.

Подготовка собственной Windows VM и технического доступа описана в
[инструкции VM](docs/windows-vm.md). Экспериментальный модуль и порядок
независимой Guest/USB-пробы — в [инструкции пилота](docs/local-pilot.md).

Основной результат подготовки — воспроизводимая установка и проверка программ
на уже существующей Windows. Ей не должны требоваться QEMU, WinRM или создание
новых учётных записей. Целевые системы — Windows x64 с повышенным административным
запуском установки. Поддержка версий определяется предпосылками программ
и возможностями Windows; фактически испытанные сборки указываются отдельно.
Эталон и диагностические сценарии служат стендом для проверки этого пути.
Вход Check/Prepare и границы его проверки описаны в
[инструкции подготовки существующей Windows](docs/windows-preparation.md).
Общая серверная поставка развивается независимо в
[prairielearn-deployment](https://github.com/Afonenko-Course-Tools/prairielearn-deployment);
экзаменационные сервисы не включаются обычным запуском курсов.

## Использование

Целевая схема: Linux VM в Proxmox имеет постоянный адрес, Windows-ПК получают
адреса по DHCP и сами опрашивают контроллер. Локально установленные сценарии
применяют согласованные политики. Опрос не скачивает и не исполняет новый код.

Во время экзамена доступны локальные IDEA, JDK и Git, а в сети — PrairieLearn,
университетский Moodle `https://edurfe.bsu.by/` и подтверждённые технические
зависимости. После экзамена обычные занятия работают без контроллера.

## Проверка

Критерии приёмки перечислены в [требованиях](docs/requirements.md).
Полный экзаменационный режим пока запрещён к применению. Список IP сам по себе
не ограничивает доступ согласованными сайтами: на IP Moodle обнаружен другой
HTTPS virtual host. Отдельная Linux-проба готового Squid подтвердила разрешение
PrairieLearn/Moodle и отказ посторонним HTTP-запросам, включая повторный запрос
в том же TLS-соединении. Первый Windows GPO-сетевой цикл также прошёл, но
повторяемость и общий клиентский путь ещё не приняты. Прежняя проба `-GuestOnly`
не входит в новый переключатель.
Проверки с подменёнными Windows API не подтверждают ограничения настоящего Guest,
очистку профиля или работу реальной флешки.

## Ограничения

В прежнем прототипе настоящий Guest на тестовой VM получил запрет чтения виртуальной флешки через
Explorer, диалог открытия IDEA и Java; проверены попытки изменить политику и вызвать
завершение. В IDEA работают обычное completion, Rename, inspections, сборка,
запуск и отладка локального проекта с JDK 25. Эти результаты предстоит повторить
на новом механизме с явными настройками.
На новом механизме независимо подтверждены удаление первого профиля после
выхода и следующий Guest с новым SID и чистым home. Plain Non-Administrators
MLGPO запретила чтение виртуальной флешки в Explorer и Java; после адресного
снятия политики обычный пользователь снова прочитал её без перезагрузки,
включая переподключение носителя. Обычные Java/Git и выбранные учебные файлы
сохранились. Это узкие нативные пробы; новый общий установщик компонентов
ещё проходит интеграционную проверку.

Остаются физические флешки, IDEA с новым применением политик, полный маршрут
Moodle/PrairieLearn, повторяемый сетевой режим и общее локальное завершение.
Широкое файловое ограничение вне домашнего каталога и привязка экзаменационного
входа к студенту/ПК ещё не реализованы. MIC дал только узкий результат;
проба Sandboxie Privacy Mode не дала рабочего стола и не принята.
Подготовка программ испытана на en-US 19045.2006 с кириллицей в путях;
официальная русская MUI дала русскую оболочку, но русский Prepare Check
не состоялся. Русская базовая ОС и остальные сборки требуют отдельной проверки.
